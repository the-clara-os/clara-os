How to build ClaraOS, start it, and work at its prompt and in its windows.

This manual is for version {{version}}. ClaraOS starts in a virtual machine, tests itself as it comes up, and ends at a prompt where what you type is Common Lisp: it is read, evaluated, and what it gives is printed. There is no shell and there are no commands apart from that. Listing a directory, writing a file and saving the whole system are Lisp forms like any other.

What the manual shows of the prompt was typed at a running kernel: the tests that every change has to pass type each of these sessions again and compare the answers. The front page says what ClaraOS is for and how far it has come.

{{spleen:Getting it}}

ClaraOS is built from its source, on macOS or on Linux. There is nothing to download but the repository, and nothing is installed on your computer: the result is a directory of files, and a disk image made of them, for a virtual machine to start from.

On macOS the tools come from Homebrew:

brew install llvm lld qemu sbcl

On Ubuntu they come from the distribution:

sudo apt install clang lld make qemu-system-x86 qemu-system-arm ovmf \
    qemu-efi-aarch64 netcat-openbsd sbcl python3 dosfstools

Then, on either:

git clone https://github.com/the-clara-os/clara-os
cd clara-os
make               # both kernels, and the Lisp files beside them
make test          # if you like: start every machine and check its answers

make takes a few seconds and leaves everything in build/. Building and running need clang, QEMU and Python 3, which macOS has with Apple's developer tools. SBCL and the rest of the list are for make test.

{{spleen:Starting it}}

Under QEMU

make run-aarch64   # virtualized on Apple silicon: it starts at once
make run-x86_64    # emulated: the firmware takes a few seconds first

A window opens, which is the machine's screen, and the terminal you started it from becomes its serial port. Both show the same report as the machine comes up, and both end at the prompt. You can type in either: in the window on the machine's keyboard, in the terminal on its serial port.

(clara.system:shut-down)at the prompt: the machine saves its world and turns itself off, and QEMU ends. Stopping it has the other ways.
Ctrl-A Xin the terminal: leave QEMU, whatever the machine is doing, which is the plug pulled
Ctrl-A Cin the terminal: QEMU's own monitor, and back
MEM=1G make run-aarch64a machine with that much memory, where it has 512 MiB otherwise
WORK=~/clara-work.img make run-aarch64a machine with a second disk, one of your own
SIZE=4096 make run-aarch64a machine whose own disk has that many MiB, where it has 1024 otherwise: A larger disk
NET= make run-aarch64a machine without a network card, where it has one otherwise
SOUND= make run-aarch64a machine without a sound card, where it has one otherwise, whose sound comes out of your computer
UTM=1 make run-aarch64a machine with the keyboard, the pointers and the sound card that UTM gives one, in place of virtio's: a USB controller with a tablet, a mouse and a keyboard, and Intel's sound card

The machine starts from a disk image, build/disk-aarch64.img or build/disk-x86_64.img, which is made of the files in build/esp the first time and kept from then on. Files that you write are on it the next time, and so is a world that you saved. A newer build does not make the disk again: make run-aarch64 hands the machine the build as a second disk, the system that is running takes it and starts the machine again, and the newer system comes up with your files where they were. A newer ClaraOS says what happens there.

FRESH=1 make run-aarch64a new disk for the machine, as if it had never run. The one that was there is kept as build/disk-aarch64-before.img.

In UTM

  1. make image, on macOS. It makes build/claraos.img, a disk with both kernels on it.
  2. In UTM: New, then Virtualize on Apple silicon (the machine is AArch64) or Emulate (x86_64), operating system Other. Skip the ISO. Leave "UEFI Boot" checked. 512 MiB of memory is plenty.
  3. Remove the drive that UTM made. Then Drives, Import, build/claraos.img, with the interface VirtIO: that is the disk ClaraOS has a driver for. With any other interface the machine still starts, and has no files.
  4. Add a Serial device, mode "Built-in Terminal". The system talks there as well as on the screen, and you can type there.
  5. The keyboard and the pointer need nothing done on a machine that is virtualized on Apple silicon: UTM gives it a USB controller with a keyboard, a mouse and a tablet, and ClaraOS has drivers for them. A machine that is emulated as x86_64 gets a USB controller of an older kind from UTM, which there is no driver for, and the report says so. For that one, under QEMU, Arguments, add two: -device virtio-keyboard-pci and -device virtio-tablet-pci. The second is the pointer, which the window manager is worked with.
  6. To fetch by HTTPS, the machine needs a device that makes random numbers. When the system's report says random: no device that makes numbers which nobody can guess, add one more argument there: -device virtio-rng-pci.
  7. Sound needs nothing done either: the card that UTM picks by itself, one of Intel's, has a driver. So has the other card that ClaraOS plays on, Virtio Sound (virtio-sound-pci), which can be chosen in the virtual machine's settings, under Sound.
  8. Start.

UTM copies the disk into the virtual machine, and that copy is the machine's from then on. To put a newer ClaraOS on it, give the machine the newer build/claraos.img as a second drive and tell the system to take it: A newer ClaraOS. To go back to a system that nothing was written on, import build/claraos.img again in place of the drive; the files that were written on the old drive go with it, and so does a world that was saved there.

What it needs of a machine

A processorx86_64 or AArch64. One is used, however many the machine has.
FirmwareUEFI. The kernel is the program that the firmware starts: there is no boot loader between them.
Memory128 MiB is enough to start and to work. It is given 512 MiB unless you say otherwise.
A diskA virtio disk with a FAT volume, of 12, 16 or 32 bits, behind either kind of table of partitions or without one, that the firmware can write to. The volume it starts from is the one whose files it sees by their plain names, and the files of another disk's have that volume's number before theirs.
A place to typeA serial port, a keyboard, or both. The keyboard is a virtio keyboard, or one that hangs from a USB controller.
A screenThe one the firmware sets up, if there is one. Without it everything is on the serial port.
A pointerA mouse or a tablet, virtio's or one of USB, for the window manager. Nothing else has a use for one.
A network cardA virtio network card, for fetching files and a newer ClaraOS. A machine without one starts and works all the same.
A sound cardA virtio sound card, or one of the kind that Intel calls High Definition Audio, for sound. A machine without one starts and works all the same, and plays nothing.

What hangs from a USB controller

A USB controller of the newest kind (xHCI) is driven, and the report names what hangs from each of its ports. A keyboard, a mouse or a tablet there is the machine's like a virtio one: both kinds can be there at once, and the pointer is one for all of them.

usb: 00:02.0 is a USB controller: 8 ports, and at them 3 devices
usb:   port 5 0627:0001 QEMU USB Tablet
usb:   port 6 0627:0001 QEMU USB Mouse
usb:   port 7 0627:0001 QEMU USB Keyboard
input: 00:02.0 port 5 is a tablet, QEMU USB Tablet
input: 00:02.0 port 6 is a mouse, QEMU USB Mouse
input: 00:02.0 port 7 is a keyboard, QEMU USB Keyboard

A device can be plugged in and pulled out while the machine runs, and the system says each as it happens. (clara.usb:devices) is what hangs from the controllers at the moment, and clara.usb:device-place and clara.usb:device-name say of one where it is and what it calls itself.

  • A USB device that is no keyboard, mouse or tablet is found and named in the report, and nothing more is done with it: there is no driver for a disk of USB, for one.
  • A device that hangs from a hub is not found, only the hub. Under QEMU that is the fourth device at one controller, for which QEMU puts in a hub by itself.
  • A controller of an older kind (UHCI, OHCI, EHCI) is named in the report and has no driver.

Stopping it

The machine is shut down by asking it to:

> (clara.system:shut-down)
clara: the world is saved
clara: turning the machine off

It saves the world, so that the next start goes on where this one left off, stops the applications, has the disk keep what was written to it, and turns the machine off: the window closes, and QEMU ends. (clara.system:start-again) does the same and then starts the machine again at once, in the world that it saved. There are three ways of asking:

At a prompt(clara.system:shut-down) and (clara.system:start-again). With :save nil the world is not saved, and the next start is in the one that was saved last, or in a new one when none was.
In the window managerShut Down and Restart, at the end of the list under Applications.
By the power buttonwhich is how a host asks a machine to stop: system_powerdown in QEMU's monitor, and Request power down in UTM. The system looks at the button four times a second.

A machine that is asked to shut down asks its windows first. A window of Emma, the editor, whose text is not saved holds it back: it comes to the top, the machine stays on, and the answer says why.

> (clara.system:shut-down)
error: the machine is not shut down: the window "/notes.txt" has text that is not saved. Finish that, or ask with :FORCE T, which goes on without

Save the text or close the window, and ask again; (clara.system:shut-down :force t) does not ask. Asked by the power button or from the list, the machine says the same on the serial port and stays on. What else goes with the machine is whatever a thread was in the middle of: a file that a program had open for writing and had not closed is not written.

Ctrl-D at the first prompt ends the session without any of this. The kernel says clara: nothing more to do, halting and the machine stands still, deaf to its power button, until the host stops it. Stopping a machine from outside, with Ctrl-A X or by closing its window, is the plug pulled. Files are safe then, since a file is on the disk from the moment the form that wrote it has answered; what the world has become since it was last saved is gone.

{{spleen:The prompt}}

The prompt is > and a space. What you type after it is a form of Common Lisp. When the line holds a whole form, the form is evaluated and its value is printed, in the way it would have to be typed to mean the same thing. Then the prompt comes back.

> (+ 1 2)
3
> (list 1 "two" 'three #\4)
(1 "two" THREE #\4)
> (floor 17 5)
3
2
> (values)
> 'one "two" (+ 1 2)
ONE
"two"
3
> (list 1 2
        3)
(1 2 3)

A form that gives several values has each of them on a line of its own, and one that gives none has nothing. Several forms on a line are answered one after the other. A form that is not finished when the line ends goes on in the next line, after a prompt of two spaces, for as many lines as it takes.

Keys

Enterends the line
Backspace, Deletetakes back the last character of the line
Taba space
Ctrl-Cwhile you type: gives up the line, and the form it was part of. While a form is evaluated: stops it.
Ctrl-Dat the start of a line: ends the session, and the machine halts

That is all the editing there is at this prompt. The arrow keys do nothing here, and no line that was typed before can be called back: that is for a REPL window, below. In a terminal on the serial port, the terminal's own copy and paste do what is missing: many forms can be pasted at once.

The keyboard is read as one of the United States, with Shift, Ctrl and Caps Lock, and a key that is held down repeats. What is typed on the serial port can be any character, as UTF-8. The screen shows the characters of ASCII, and a box for any other; in a window, an emoji is its picture.

A REPL window has the same keys, and more: there Ctrl-D closes the window, and the machine goes on; the arrows up and down bring back the lines that were typed before; and Page Up and Page Down show what has left the window. It also shows which parentheses of what you type belong together, and what it shows can be highlighted, copied and put in again, Ctrl-C and Ctrl-V.

The screen holds 100 columns and 37 rows at 800 by 600 pixels, and what scrolls off its top is gone: that is the screen of the first prompt, before there are windows. A REPL window keeps its rows, and the terminal on the serial port keeps whatever a terminal keeps.

Mistakes

A mistake costs a line. The system says what went wrong, in words, and the prompt comes back with everything as it was.

> (car 5)
error: CAR wants a list, and 5 is not one
> (no-such-function 1 2)
error: the function NO-SUCH-FUNCTION is not defined
> (loop)
Ctrl-C
error: interrupted from the keyboard

A form that does not end, like that (loop), runs until Ctrl-C stops it. So does one that waits for something that never comes.

{{spleen:The language}}

The Lisp is a part of Common Lisp, and not a dialect of its own: what is here means what it means in any Common Lisp, and a program that keeps to this part runs elsewhere as it stands. If you know Common Lisp, read where it stops short and go on. If you do not, any introduction to it will do, for as far as this part goes.

What you type is compiled before it runs, by a compiler that is written in this Lisp like the rest of the system, and what the compiler makes is written out once more as the instructions of the machine's own processor, which then runs it with nothing in between. The system runs the same way: its console, disks, file system and windows are written in this Lisp.

A number is an integer of 63 bits, between -4611686018427387904 and 4611686018427387903. A result outside that is an error and not a wrong number, and so is a division that does not come out even: there are no larger integers, no fractions and no decimal numbers yet. A character is a Unicode code point, and a string holds any of them. make-string makes a new string of a length, with the character that :initial-element names in every place, or the character of code 0 when none is named, and (setf (char string index) character) changes one place of a string. find and position look into a list, a string or a vector for something, and find-if and position-if for what a function is true of: find gives what it found and position the place where it is, counted from 0, and both NIL when there is none. :start and :end name the part to look at, :from-end t asks for the last one in it and not for the first, :key is a function that says what of each element is looked at, and :test, for the two that are given the thing itself, is the function that compares, eql when none is named. A part that is not there is an error. destructuring-bind takes a list apart into variables, by a list of parameters like a macro's: lists within the list, and &optional, &rest and &key.

Text by a pattern

> (format nil "~A has ~D file~:P, ~:D bytes in all" "the disk" 3 1048576)
"the disk has 3 files, 1,048,576 bytes in all"
> (format nil "~{~A~^, ~}" '(1 2 3))
"1, 2, 3"
> (format nil "~10A|~10@A|~8,'0D|" "left" "right" 42)
"left      |     right|00000042|"
> (format nil "#x~X, #b~B, ~R, the ~:R, ~@R" 255 5 42 3 1994)
"#xFF, #b101, forty-two, the third, MCMXCIV"
> (format t "~{~A:~10T~A~%~}" '(name "Clara" version 62))
NAME:     Clara
VERSION:  62
NIL

"yes, many, Hello there"
> (format nil "~:{~A is ~A~:^; ~}" '((one 1) (two 2)))
"ONE is 1; TWO is 2"
> (format nil "~,2F" 1)
error: FORMAT does not know the directive #\F in "~,2F"

format writes text by a pattern, its control string: the text as it stands, and in it directives, each a tilde and a character, that say what to write of the arguments. The first argument of format is where the text goes: nil for a string that is given back, t for *standard-output*, or a stream. Between the tilde and the character a directive can have parameters, with commas between them, and a colon, an at-sign or both, which change what it does: ~8,'0D is a number in eight columns with noughts before it. A parameter is a number, a character after a quote, V for the next argument, or # for how many arguments are left; one that is left out is what the directive takes it to be.

~A ~SAn argument as princ and as prin1 write it. ~10A is ten columns wide at the least, with the text at the left, and ~10@A with the text at the right; the further parameters are by how many columns the width grows, how many blanks there are at the least, and the character to pad with. With a colon NIL is (). ~W is ~S without parameters.
~D ~B ~O ~XAn integer, in tens, twos, eights and sixteens. ~8D is eight columns wide with the number at the right, ~8,'0D pads with noughts, ~:D puts a comma between every three digits, and ~@D writes the sign of a number above nought too. The third and fourth parameters are another character for the comma and another count of digits. Anything that is no integer is written as ~A writes it.
~RAn integer in words, forty-two; ~:R as a place in a row, forty-second; ~@R in Roman numerals, XLII, from 1 to 3999, and ~:@R in the older ones, IIII for IV, to 4999. With a parameter it is the radix, from 2 to 36, and the rest are the parameters of ~D: ~2R is ~B.
~CA character. ~:C writes the name of one that shows nothing, Space, and ~@C writes it the way it is typed, #\a.
~% ~& ~| ~~A new line; a new line unless the text is at the start of one; a new page; a tilde. A parameter says how many. A tilde at the end of a line of the control string takes the end of that line and the blanks that begin the next out of the text, so that a long control string can go on in the next line of a program.
~TBlanks as far as a column, the first of a line being 0: ~10T. When the line is there already, as far as the next column that is so many columns further as the second parameter says, one when there is none. ~3@T is three blanks, and with a second parameter then on to a column that it divides.
~*Passes over an argument, or as many as the parameter says. ~:* goes back by one, so that the argument is written again, and ~2@* goes on with the third, the first being 0.
~?Two arguments, another control string and the list of its arguments, are written in this place. With ~@? the other control string takes its arguments from the ones that are here.
~( … ~)What is written between them is written in small letters; with a colon each word begins with a capital, with an at-sign the first one does, and with both all the letters are capitals.
~[ … ~]One of the parts between them, which ~; divides, is written: the one that an argument counts to, the first being 0, and none when there is no such part, or the last one when ~:; stands before it. ~:[ has two parts, the first for NIL and the second for anything else. ~@[ has one, which is written when the argument is not NIL, and the argument is then still there for a directive in it.
~{ … ~}What stands between them is gone through again and again with the items of a list, which is the argument, for as long as there are items. ~@{ takes the arguments that are left in place of a list; ~:{ takes a list of lists, one for each time through, and ~:@{ the arguments that are left as such lists. A parameter is the number of times at the most, and ~:} at the end has it gone through once even with nothing to take.
~^Leaves what it stands in when no argument is left: a time through ~{ and all that would follow it, which is how "~{~A~^, ~}" writes no comma after the last item, or else the control string. ~:^ leaves a ~:{ when no list is left for it.
~PAn s unless the argument is 1. ~:P asks the argument before it, which a directive has written already, and ~@P writes y or ies.
~< … ~>The parts between them, which ~; divides, are written in a field as wide as the first parameter says, the first part at its left edge and the last at its right, with the blanks shared out between them. One part alone is written at the right. A colon puts blanks before the first part as well, and an at-sign after the last.

The directives for numbers with a fraction, ~F, ~E, ~G and ~$, are not there, since there are no such numbers, nor are the pretty printer's, ~_, ~I, ~/, ~:T and a ~< that ends in ~:>. ~T counts the columns of a line that began in the same call of format, or from where that call began to write. And what is no integer is written by ~X and the others as it is, with the numbers in it in tens. What an error says is written by the same pattern, so (error "~D file~:P could not be read" 2) says what it should.

error: the stack is full: the forms are nested too deep, or a function calls itself without end

An error is a condition, with a type. handler-case takes the conditions whose type one of its clauses names, and unwind-protect cleans up whichever way its form is left. The system's own errors have Common Lisp's types where a program would want to tell them apart: type-error, division-by-zero, unbound-variable, undefined-function and their kin. A stack or a heap that is full, and Ctrl-C, are no errors: ignore-errors and a clause for error let them pass, and a clause for serious-condition takes them.

Where it stops short

What is refused is refused with an error that says so. Nothing is quietly taken for something else, so a program does not mean one thing here and another elsewhere.

  • Numbers are integers of 63 bits. No larger integers, no ratios, no floating point.
  • loop is the plain one, a body that is repeated until a return. Its keywords, for and collect and the rest, are not there. do, dolist and dotimes are.
  • format has its directives but the ones for numbers with a fraction, ~F, ~E, ~G and ~$, and the pretty printer's, ~_, ~I, ~/, ~:T and ~< to ~:>. Its control string is a string, not a function, and there is no formatter.
  • A time is taken apart, by decode-universal-time and get-decoded-time, and not put together: there is no encode-universal-time. A time zone is a whole number of hours, and nothing knows of daylight saving time.
  • The functions on sequences, mapcar, remove-if, sort and the others, take lists. length, subseq and concatenate take strings as well, and find, find-if, position and position-if strings and vectors, with all their keyword arguments but :test-not. Of the keyword arguments of the others there is :test, with :key for member, assoc and sort, and :initial-value for reduce.
  • make-string takes :initial-element and not :element-type: there is one kind of character, and one kind of string.
  • defstruct takes a name and slots, and none of its options.
  • Conditions are handled by handler-case. There is no handler-bind, no restart and no debugger.
  • There are no hash tables. Classes and generic functions are there, and their chapter says what of them is not.
  • A package can be made, used when it is made, exported from, and deleted when no other uses it. Nothing is imported or shadowed afterwards.
  • eq and eql are the same function. Letters change case as far as ASCII has them: (string-upcase "é") is "é".
  • A function can call itself some six thousand calls deep. Past that it is the error above, and not the end of the machine.
  • (declare (special ...)) and &environment are refused, and so are the reader's #., #S and #P.

Everything that is defined, at the end of this manual, is the whole list, by subject.

{{spleen:Objects}}

Common Lisp's object system is here, the part of it that programs are written with. A class says what its instances hold, their slots, and which classes it is a kind of. A generic function is a function whose behaviour is put together from methods, each written for arguments of some classes, and a call runs the methods that fit the arguments it was given. It is written in this Lisp, like the compiler, and the system's own types are classes in it: you can write a method for an integer, a string, a structure or a condition as well as for an instance of a class of yours.

defclass takes a name, the classes that the new one is a kind of, and the slots. A slot is a name, or a name with what is said about it: :initarg, the keyword that fills it when an instance is made; :initform, a form for the value that it begins with otherwise, evaluated for each instance; :reader, :writer and :accessor, the names of functions that read it, write it, or both, an accessor being written with setf; and :allocation :class for a slot that the instances have between them. After the slots, (:default-initargs :balance 10) gives make-instance the arguments that a caller leaves out.

make-instance takes the name of a class and keywords with their values. A keyword that fills no slot is refused, which is how a keyword that was typed wrongly is found. A slot that got no value has none: reading it is an error, slot-boundp asks, and slot-makunbound takes a value away again. slot-value reads a slot by its name and setf writes it, slot-exists-p says whether an instance has such a slot, and inside with-slots the names of slots stand for the slots themselves, as the names that with-accessors gives stand for calls of the functions that read them.

A class that is a kind of another

> (defclass savings (account) ((rate :initarg :rate :initform 2 :reader rate)))
#<STANDARD-CLASS SAVINGS>
> (defvar *savings* (make-instance 'savings :owner "Julio" :balance 1000))
*SAVINGS*
> (list (owner *savings*) (balance *savings*) (rate *savings*))
("Julio" 1000 2)
> (list (typep *savings* 'savings) (typep *savings* 'account) (typep *account* 'savings) (type-of *savings*))
(T T NIL SAVINGS)

An instance of a class has the slots of every class above it, and is an instance of each of them. A class can be a kind of several, (defclass amphibian (boat car) ()). The classes above a class are then put in one order, its precedence list, in which a class comes before the ones it is a kind of and those come in the order in which they were written. When two definitions ask for orders that cannot both be had, the class is refused. The classes that it names have to be there already.

Generic functions and methods

> (defgeneric withdraw (account amount))
#<STANDARD-GENERIC-FUNCTION WITHDRAW (0)>
> (defmethod withdraw ((account account) amount)
    (when (> amount (balance account))
      (error "~A has only ~D" (owner account) (balance account)))
    (decf (balance account) amount))
#<STANDARD-METHOD WITHDRAW (ACCOUNT T)>
> (withdraw *account* 50)
300
> (withdraw *account* 1000)
error: Clara has only 300
> (defmethod withdraw :before ((account savings) amount)
    (when (> amount 500) (error "no more than 500 at a time comes out of savings")))
#<STANDARD-METHOD WITHDRAW :BEFORE (SAVINGS T)>
> (withdraw *savings* 600)
error: no more than 500 at a time comes out of savings
> (withdraw *savings* 100)
900
> (defmethod withdraw :around ((account account) (amount (eql 0))) 'nothing-to-do)
#<STANDARD-METHOD WITHDRAW :AROUND (ACCOUNT (EQL 0))>
> (withdraw *savings* 0)
NOTHING-TO-DO
> (defgeneric describe-account (account)
    (:method ((account account)) (list (owner account) (balance account)))
    (:method ((account savings)) (append (call-next-method) (list :rate (rate account)))))
#<STANDARD-GENERIC-FUNCTION DESCRIBE-ACCOUNT (2)>
> (list (describe-account *account*) (describe-account *savings*))
(("Clara" 300) ("Julio" 900 :RATE 2))

A method says, for each parameter that must get an argument, which arguments it is for: (account account) is a parameter for an instance of that class or of a class below it, (amount (eql 0)) one for that very object, and a bare name one for anything. A call runs the most specific method that fits. Inside it, (call-next-method) calls the next one that fits and gives its values, with the same arguments or with others, and (next-method-p) says whether there is one. When several parameters are for classes, the first one in which two methods differ decides which is the more specific.

A word between the name and the parameters says when a method runs. The :before methods run first, the most specific first, and the :after methods last, the most specific last; neither has a say in the value. An :around method runs before all of them and in place of them, unless it calls (call-next-method), which is the rest. defgeneric says what the parameters are and can hold methods of its own; a defmethod for a name that has no generic function makes one. A method that is defined again, for the same classes and with the same word, takes the place of the one before.

> (defgeneric size (thing)
    (:method ((thing string)) (length thing))
    (:method ((thing list)) (length thing))
    (:method ((thing integer)) thing)
    (:method ((thing point)) 2)
    (:method ((thing low-fuel)) (fuel-left thing))
    (:method ((thing account)) (balance thing)))
#<STANDARD-GENERIC-FUNCTION SIZE (6)>
> (mapcar #'size (list "four" '(1 2 3) 5 nil (make-point :x 1) (make-condition 'low-fuel :left 7) *account*))
(4 3 5 0 2 7 300)
> (size #\a)
error: SIZE has no method for the arguments (#\a)

A generic function is a function. What defgeneric gives back is the function itself, the same one that #'double names below: it can be called, kept in a variable and handed to mapcar like any other, and it is written with its name and the number of its methods. Its class is standard-generic-function, a kind of generic-function, which is a kind of function, so a method can be written for the functions that have methods and another for all the rest.

> (defvar *double*
    (defgeneric double (thing) (:method ((thing integer)) (* 2 thing))))
*DOUBLE*
> (list (funcall *double* 21) (eq *double* #'double) (functionp *double*))
(42 T T)
> (defmethod double ((thing string)) (concatenate 'string thing thing))
#<STANDARD-METHOD DOUBLE (STRING)>
> (list *double* (mapcar *double* '(1 "ab")))
(#<STANDARD-GENERIC-FUNCTION DOUBLE (2)> (2 "abab"))
> (list #'withdraw (class-name (class-of #'withdraw)))
(#<STANDARD-GENERIC-FUNCTION WITHDRAW (3)> STANDARD-GENERIC-FUNCTION)
> (defgeneric made-of (f)
    (:method ((f function)) 'code)
    (:method ((f generic-function)) 'methods))
#<STANDARD-GENERIC-FUNCTION MADE-OF (2)>
> (mapcar #'made-of (list #'car #'double (lambda (x) x) #'made-of))
(CODE METHODS CODE METHODS)

The classes that the language begins with: t, which everything is; number, real, rational and integer; character; symbol; sequence, list, cons and null, which is the class of nil, a symbol and a list at once; array, vector and string; function, with generic-function and standard-generic-function below it; package and stream. A type that defstruct made is a class, below structure-object, and so is a type of condition.

A function that setf writes with is a generic function of the name (setf balance), which gets the new value before its other arguments: :accessor makes one, and (defmethod (setf balance) :after (value (account account)) ...) adds to it like to any other.

When an instance is made

> (defclass audited (account) ((entries :initform nil :accessor entries)))
#<STANDARD-CLASS AUDITED>
> (defmethod initialize-instance :after ((account audited) &key)
    (push (list 'opened (balance account)) (entries account)))
#<STANDARD-METHOD INITIALIZE-INSTANCE :AFTER (AUDITED)>
> (defmethod withdraw :after ((account audited) amount)
    (push (list 'withdrew amount) (entries account)))
#<STANDARD-METHOD WITHDRAW :AFTER (AUDITED T)>
> (let ((account (make-instance 'audited :owner "Gray" :balance 10)))
    (withdraw account 4)
    (entries account))
((WITHDREW 4) (OPENED 10))

make-instance makes the instance and calls initialize-instance with it and the arguments, which fills the slots; a method of yours for it, :after most often, does what else a new instance needs. A keyword that such a method takes is one that make-instance takes for the class. shared-initialize is the part that fills slots, and reinitialize-instance fills slots of an instance that is there. What goes wrong is a generic function too, for a class to give its own answer: slot-unbound, slot-missing, no-applicable-method and no-next-method.

How an instance is written

#<STANDARD-METHOD PRINT-OBJECT (ACCOUNT T)>
> (list *account* *savings*)
(#<ACCOUNT Clara 300> #<SAVINGS Julio 900>)

"#<ACCOUNT Clara 300> is its owner's"
> (defstruct coin value)
COIN

An instance is written as its class and its address between #< and >, which says that there is no text to read it back from. The address is where the instance lies in memory, a number in hexadecimal between braces. No two objects have the same one, and an object keeps its own for as long as it is there, in a world that is saved and comes back as well: it tells one instance from another that looks the same, and it is another number on your machine than on this page.

A method of print-object for its class writes an instance as you like, wherever it is written: at the prompt, by format, inside a list. It is given the object and a stream, and print-unreadable-object writes the #< and the > around what its body writes, with the name of the class first when :type says so and the address last when :identity does. It takes any object: an integer or a character lies nowhere in memory, and gets no address. The same goes for the structures of a type that you write such a method for.

A class that is defined again

> (defclass account ()
    ((owner :initarg :owner :reader owner)
     (balance :initarg :balance :initform 0 :accessor balance)
     (currency :initarg :currency :initform 'euros :accessor currency)))
#<STANDARD-CLASS ACCOUNT>
> (list (currency *account*) (currency *savings*) (balance *savings*) *account*)
(EUROS EUROS 900 #<ACCOUNT Clara 300>)

A class can be defined again, as a function can, and what is there follows: the classes below it, and every instance, which has the slots of the new definition the next time it is used. A slot that it had keeps its value, a new one begins as the class says, and one that is gone is dropped. The methods stay, apart from the ones that the old definition made for its slots. A world that is saved keeps its classes, its methods and its instances, and what you type of them is kept as text like any definition:

> (list *account* (withdraw *savings* 100) (currency *savings*))
(#<ACCOUNT Clara 300> 800 EUROS)

Types

> (list (typep 5 'integer) (typep "five" 'sequence) (typep nil 'list) (typep 5 '(or string symbol)))
(T T T NIL)

    (typecase thing
      (integer 'a-number)
      ((or string symbol) 'a-name)
      (account 'an-account)

(A-NUMBER A-NAME A-NAME AN-ACCOUNT SOMETHING-ELSE)

A class is a type. typep asks whether an object is of one, by the name of a class or by the class itself, which find-class gives for a name and class-of for an object; type-of is the name of an object's class. It also knows the names atom, keyword, fixnum and boolean, and the types that are put together of others: (or integer string), (and ...), (not ...), (member a b c), (eql 5) and (satisfies evenp). typecase takes the first clause whose type its object is of, and etypecase is the same with an error when none is.

Where it stops short

  • Methods are put together in the one way that is described above, the standard one. There is no define-method-combination, and defgeneric takes :method, :documentation and nothing else.
  • There is no change-class, and no metaobject protocol: a class is of the class standard-class, and :metaclass is refused. Only a class that defclass made can have a class below it.
  • A function (setf name) is made by defgeneric, defmethod, :accessor or :writer. (defun (setf name) ...) and #'(setf name) are not there.
  • There is no find-method, remove-method, add-method or ensure-generic-function: a method that was defined by mistake stays, until one for the same classes takes its place.
  • The keywords that a generic function is called with are not held against the ones its methods take, as they are when an instance is made.
  • A condition is written as the system writes one, whatever method of print-object is written for its type.
  • Only an instance is written with its address by itself. A function, a thread, a lock and an event have no text to read back either, and are written without one: two functions that have no name look alike.
  • typep knows the types above and no others: not (integer 0 9), not (unsigned-byte 8). There is no subtypep, check-type, deftype or coerce.
  • A function of the system's cannot be made a generic function: (defmethod car ...) is refused.

{{spleen:The compiler}}

Whatever you define is compiled. The compiler goes through a function once and writes down what an interpreter would have to find out again at every call: where each variable is, which form is a call and which a loop, what every macro stands for. What it leaves is a list of small steps, instructions, which are translated for the machine's processor in turn, and the processor runs the function. That happens when a form is typed at the prompt, when a file is loaded and when eval is given a form, so there is nothing to ask for:

> (compiled-function-p #'fact)
T
> (compiled-function-p (lambda (n) (* n n)))
T
> (funcall (compile nil '(lambda (n) (* n n))) 12)
144

The system is compiled in the same way. The console, the file system, the window manager, the applications and the compiler itself are Lisp, and when a machine starts from the Lisp files the compiler first compiles itself, what translates for the processor then translates the compiler and itself, and everything after that is compiled and translated as it is loaded. That takes half a second, or some ten seconds where the machine is emulated. A world that is saved holds all of it compiled, and a machine that starts from one does none of that work again.

compile is still there: (compile nil '(lambda ...)) gives the compiled function of a form, as above, and (compile 'fact) leaves a function that is compiled already as it is.

How quick

time evaluates a form and says how long that took, to a hundredth of a second, which is how often the system's clock ticks. On one machine:

> (defun fib (n) (if (< n 2) n (+ (fib (- n 1)) (fib (- n 2)))))
FIB
> (time (fib 30))
10 milliseconds
832040

The interpreter that ClaraOS had before it had a compiler, which walked the text of fib at every call, took 390 milliseconds for the same on that machine, and the compiler's instructions took 70 when the kernel carried them out, before they were translated for the processor.

What it made of a function

disassemble writes the instructions of a function out, with their numbers:

> (disassemble 'fact)
FACT: 1 local variable, 4 words of stack, translated for the processor
0   LOCAL 0
1   CONST 2
2   <
3   JUMP-IF-NIL 6
4   CONST 1
5   RETURN-ONE
6   LOCAL 0
7   CONST FACT
8   LOCAL 0
9   CONST 1
10  -
11  CALL 1
12  *
13  RETURN
NIL

The instructions work on a stack. LOCAL puts the value of a variable on it, which is known by its number: n is variable 0. CONST puts a constant there. < takes two numbers off the stack and leaves T or NIL, so the first three are (< n 2), and JUMP-IF-NIL 6 goes on at instruction 6 when that gave NIL. CALL 1 takes an argument off the stack and the function under it, calls it, and leaves what it gives. The rest is (* n (fact (- n 1))).

A function is found by its name at the moment it is called: define fact again, and compiled code calls the new one. The commonest functions of the kernel have an instruction each, which does the work without a call: car, cdr, not, null, consp, atom, 1+ and 1- of one argument, and cons, eq, +, -, *, <, >, <=, >=, =, aref and svref of two. Such an instruction looks first whether its name still means the kernel's function. If you have defined * again, it calls yours.

Given a lambda form, disassemble shows what compiling it makes. A function that is part of the kernel has no listing.

For the processor itself

The instructions that the compiler leaves are for a machine that the kernel plays: it takes them one at a time, and finds out for each what it asks for. A function is not run that way. ClaraOS makes of those instructions the instructions of the processor itself, AArch64's or x86-64's, which the processor carries out with nothing in between, and it does so for whatever is compiled: what you define, and the system, from mapcar to the compiler.

> (list (clara.native:translated-p 'fact) (clara.native:translated-p 'mapcar))
(T T)

clara.native:translated-p says whether the processor runs a function, or the function of a name. A translated function means what it meant: its mistakes are reported in the same words, and it is found by its name at every call. disassemble lists the compiler's instructions, since those are what the processor's were made of, and says translated for the processor on the first line.

The kernel's machine is still there, and runs what is compiled while clara.native:*translate* is NIL. Functions of the two kinds call each other freely. clara.native:translate takes such a function, or the name of one, and has the processor run it from then on, with every function that was made of it before; clara.native:translate-all does the same for every function that there is, and says how many the processor runs that it did not run before.

> (setq clara.native:*translate* nil)
NIL
> (defun square (n) (* n n))
SQUARE
> (setq clara.native:*translate* t)
T
> (list (clara.native:translated-p 'square) (square 12))
(NIL 144)
> (clara.native:translate 'square)
SQUARE
> (list (clara.native:translated-p 'square) (square 12))
(T 144)
> (clara.native:translate-all)
0

The variable counts at the moment a form is compiled. Set it at the prompt, as above, or bind it around a compile or a load: (let ((clara.native:*translate* nil)) (load "/mine.lisp")). A let around a defun that is typed changes nothing, because the whole form is compiled, and translated, before the let has bound anything.

How much quicker the processor is depends on what a function does. On one machine, with fib compiled for the kernel's machine first:

> (time (fib 35))
750 milliseconds
9227465
> (clara.native:translate 'fib)
FIB
> (time (fib 35))
70 milliseconds
9227465

What gains most is what the processor does alone: the calls from one function to another, the variables and the jumps, and adding, subtracting and comparing small numbers. Fifty million additions in a loop take 610 milliseconds on the kernel's machine and 70 on the processor. What makes lists gains least, because a cons has to be made either way: a million items pushed, reversed and mapped over take 60 milliseconds there and 50 here.

  • The processor's instructions take about four times the memory of the compiler's, and a function keeps both: the listing is of the compiler's, and the kernel's machine does an instruction for the processor when it gets something that it does not usually get, a number too large or a car of what is no list.
  • A function whose instructions for the processor would be longer than a megabyte is left to the kernel's machine on AArch64, where a jump of the processor's reaches no further. clara.native:translated-p says NIL for it, and nothing else tells.
  • They are part of the world that is saved, and come back with it.

What to keep in mind

  • A macro runs when a call of it is expanded, and for a compiled function that happened once, when the function was compiled. Define a macro again, and the functions that were compiled with the old one go on as they were until they are defined again. Macros are compiled like functions.
  • The macros of a macrolet run while the forms around them are compiled, so they cannot use the variables of the function that they are written in. They can use the macros of a macrolet around them.
  • defvar has to come before the functions that bind the variable. That is the order a file has them in anyway.
  • A form that is not what it should be, (if) for one, does not stop the compiler. The compiled function fails when it comes to that form.
  • The kernel still has its interpreter. It runs the first two Lisp files when a machine starts from them, until the compiler has compiled itself, and at every such start the kernel holds what compiled code does against it: some four hundred small programs have to give the same answers both ways.

Compiled functions are part of the world that is saved. (clara.compiler:evaluate form) is the function that eval calls: the form is compiled, and then run.

{{spleen:Files}}

The system reads and writes the files of the disk it started from. The name of a file is a string: the directories that lead to it and then its own name, with a slash before each, as in "/EFI/BOOT/BOOTX64.EFI". Letters match in either case. There is no current directory: every name starts at the top of the volume. A machine with a second disk has a volume for each, and a name says which one it means by a number and a colon before everything else, "2:/mine.lisp"; a name that says none is on the disk that the machine started from.

What is there

> (directory "/*")
("/clara/" "/EFI/" "/home/")
> (directory "/EFI/BOOT/*")
("/EFI/BOOT/BOOTAA64.EFI" "/EFI/BOOT/BOOTX64.EFI")
> (probe-file "/efi/boot/bootaa64.efi")
"/efi/boot/BOOTAA64.EFI"
> (probe-file "/nothing.lisp")
NIL

directory takes a pattern, in which * stands for any characters in the last part of the name, and gives the names that fit, a directory's with a slash at its end. probe-file gives the name of a file as the disk spells it, or NIL when there is none.

A disk has three directories once the machine has started from it. /EFI/BOOT holds the two kernels, where the firmware looks for the one to start. /home is yours, and is where the system keeps what you define as text. /clara is the system's own: it holds a directory for the system that runs, named after it, and in time the world that was saved. A system's name is its version and eight digits that are different for every build, so the names of its files are asked for and not spelt out:

> (clara.system:system)
"{{version}}-8f3a1c2e"
> (clara.system:system-file "boot.lisp")

Reading and loading

> (with-open-file (in (clara.system:system-file "listener.lisp")) (list (read-line in) (read-line in)))
(";;;; listener.lisp: read, evaluate, print" ";;;;")
> (load (clara.system:system-file "listener.lisp"))
T

with-open-file opens a file for the forms inside it and closes it afterwards. read-line gives the next line, and at the end of the file it is an error, or the value you name: (read-line in nil 'done). load evaluates the forms of a file one after the other, as if they had been typed. When a form in it fails, the error says the file and the line.

A file is opened for writing with :direction :output, and whatever prints to a stream prints to it: format, write-line, print. The file is made when with-open-file is over. If the forms inside it fail, no file is made, and one that was there stays as it was.

:if-existswhen there is a file of that name already
:erroran error, which is what happens when nothing is said
:supersedethe new file takes its place
:appendwhat is written goes after what the file holds
nilno stream: open gives NIL, and nothing is written

What to know about files as they are now:

  • A file is text, in UTF-8. It is read whole when it is opened and written whole when it is closed, so it has to fit in memory, which a text does. (clara:copy-file "/hello.lisp" "/letters/hello.lisp") makes a file of the second name that holds what the first holds, byte for byte, whether that is text or not, in place of one that was there; it goes through memory whole as well.
  • A name can be 255 characters long and have spaces in it. It cannot have any of " * : < > ? \ | in it, or end in a dot or a space.
  • A file goes into a directory that is there. (clara.fat:make-directory "/letters") makes one, and (clara.fat:remove-directory "/letters") takes one away that has nothing in it. A file cannot be renamed. It is moved by copying it and deleting the one before, which is what Jaid does when it moves one.
  • There is no clock in the system, so every file it writes is dated the first of January 1980.
  • The disk is a FAT volume, which other systems read. On macOS, build/claraos.img opens with a double click, and the files that ClaraOS wrote are in it.

A disk of your own

The disk that the machine starts from is the system's, and your files are on it beside the system. A machine can have a second disk that is yours alone: nothing here ever makes it again, nothing is written to it that you did not write, and it can be given to another machine, or to a new disk of the system's. Make one once, a FAT volume with nothing on it, somewhere outside build:

mkdir -p build/empty && python3 tools/mkdisk.py build/empty ~/clara-work.img

That is a disk of 35 MiB; --size 1024 before build/empty makes one of 1024, most of which takes no room on your computer until something is written there. Then name it when you start the machine:

WORK=~/clara-work.img make run-aarch64

With export WORK=~/clara-work.img in your shell's profile, every make run-aarch64 has it. The report shows two disks then, each with a volume, and says where names are looked up:

The first is the system's, so nothing has changed for the files so far. A name that says no volume is looked up on the one that clara.fat:*volume* holds, which is the first as the machine starts; (clara.fat:volumes) gives the volumes themselves, in the same order. To work on your disk for a while, set the variable to yours: then every name without a number is looked up there, in every thread, so Emma and Jaid, the editor and the file browser, open and save there when they are told such a name. A let around a form does the same for the forms inside it and for nothing else.

Two things do not follow the variable, as the form in the middle shows for the first, and a name that says its volume does not either. The world is saved on the disk that the machine was started from, since that is where a machine looks for one, and what you define is written down there as well. The applications start either way: the system finds its own files where it started from.

The next time the machine starts, your disk is as you left it, whatever became of the system's in the meantime. A world that was made anew, by a newer system for one, has what you defined at a prompt, and not what a file of this disk defined. One line brings that back, at a prompt or in /home/init.lisp:

> (load "2:/mine.lisp")
T
> (mine)
"kept on a disk of my own"

A file of yours that loads all the others makes that the only line to type in a new world. What to know about such a disk:

  • A volume has its number from where its disk stands among the machine's, which is the order of the report. Started without your disk, the machine has no 2:: a name that begins so is an error then, which says which volumes there are, and probe-file and directory give NIL for it. The volumes are found anew at every start, so a volume that clara.fat:*volume* has kept since before the machine was started again, in a world that was saved, is refused: ask (clara.fat:volumes) for yours again.
  • The host opens the disk as well: on macOS with a double click, like the system's. That is the way to carry files in and out, and the whole disk is one file, which is easy to keep a copy of.
  • The host and the machine must not have it at the same time, since each would write without knowing of the other. On macOS, make run-aarch64 ejects a disk that is still open in the Finder before it starts the machine, and says so in the terminal; when something on the Mac is still using the disk, it says that and starts nothing. The other way round nothing stops you, so stop the machine before you open the disk on the host.
  • Any FAT volume will do, as large as you like, made with whatever the host has for that. A disk image that macOS made is one, a .dmg as well, as long as it is a plain read/write image and not a compressed or a sparse one: WORK=~/clara-work.dmg make run-aarch64. The one above has 33 MiB, which is room for a great many texts.

{{spleen:Saving the world}}

Everything that you define lives in the machine's memory, and is gone when the machine stops, unless you save it. clara:save-image writes the whole Lisp world to one file on the disk, as it is at that moment. (What you define at a prompt is also written down as text, as you go, which is what a world is made of again when the saved one cannot be used.)

> (clara:save-image)
"/clara/clara.image"

The next time the machine starts, it finds that file and takes it for its world, in place of loading the Lisp files. The report says so:

lisp: the heap is an image: 2470 KiB that ClaraOS {{version}} saved, from clara.image on the boot volume
lisp: and with it 781 KiB of code for the processor

The second line is what the world's functions are for the processor, which is saved with them. And at the prompt, what was defined is defined:

> (list (fact 10) (compiled-function-p #'fact) (clara.native:translated-p 'fact))
(3628800 T T)
> (hello)
hello from a file
NIL
> (list (depth) (point-x (make-point :x 1)) (unless-zero 2 'two))
(0 1 TWO)
> (probe-file "/clara/clara.image")
"/clara/clara.image"

What comes back, and what does not

  • Functions, macros, structures, packages and conditions that were defined, and the values of variables, come back. So does the package that names were being read in. All of it is compiled and translated for the processor, and comes back as it was.
  • A special variable comes back with the value it has outside every let, also when it was saved from inside one.
  • Threads do not come back. The world starts again at the prompt, and does not go on in the middle of what it was doing. A thread that was running is one that has been stopped, and a lock that was held is free.
  • The window manager is running again when it was running, with one REPL window. The windows that were open do not come back.
  • The devices are found again, as at every start. A world can be saved on one machine and started on another that has other devices, or another screen, as long as it is the same kind of processor.
  • Files are on the disk either way, and have nothing to do with the image.
  • What you defined after the world was saved, on a machine that was then stopped without a shutdown, is not in the image. It is in the text, and the start loads it from there.

Saving again writes a new image in place of the old one. A world of this size takes a fraction of a second to save. Shutting the machine down saves it as well, unless it is told not to.

Room for a world

A world is as large as what is in it. One that the system has just made takes some 7 MiB of the disk, and one that has been worked in for a few hours can take twice that. It is written beside the world that was saved before, which goes once the new one is whole, so that the disk has a world on it at every moment. When the disk has no room for the two, the older one goes first and the new one is written where it was. A machine that is switched off at that moment has no world on its disk, and its next start makes one from the Lisp files and from the text, as after an upgrade.

When the disk has no room for the world even so, the world is not saved, and the one that was saved before is still there:

error: the world takes 14.6 MiB, and the disk that it is saved on has room for 10.2 MiB, even with the world that was saved before gone: files have to go from that disk, or the machine needs a larger one

A machine that is asked to shut down or to start again saves first. So it stays, and says how it goes without saving:

clara: the machine is not shut down: the world takes 14.6 MiB, and the disk that it is saved on has room for 10.2 MiB, even with the world that was saved before gone: files have to go from that disk, or the machine needs a larger one
clara:   (clara.system:shut-down :save nil) does it without saving the world

Without saving, the next start is in the world that was saved last, and what was defined since comes from the text. (clara.fat:free-bytes) says how much room the disk has, and Jaid or delete-file takes away what is not needed there.

A larger disk

Under QEMU the machine's own disk, build/disk-aarch64.img, has 1024 MiB. That is room for the largest world that a machine of 512 MiB can save, twice, and for your files beside it. Most of such a disk is nothing, and takes no room on your computer until the machine writes there. SIZE=4096 make run-aarch64 gives a machine more. A disk that is smaller than what is asked for, as every disk was that a ClaraOS up to 0.0.54 made, 35 MiB, is made again with every file that it holds the next time the machine is run, and the disk that was there is kept:

tools/run.sh: the disk of this machine had 35 MiB, and is to have 1024: every file of it is on a disk of that size now,
    build/disk-aarch64.img, and the disk that was there is kept as build/disk-aarch64-small.img

The machine starts from the new disk in the world that it saved on the old one. Once it has, the old disk is yours to delete. SIZE= make run-aarch64 leaves a disk as it is.

A disk that make does not run is made larger by hand, with its machine shut down: python3 tools/mkdisk.py --size 1024 --grow claraos.img larger.img puts every file of the first disk on a second one of 1024 MiB, and only reads the first. The second is then given to the machine in place of the first; in UTM, as a drive that is imported, like the one that the machine was made with.

Going back to the files

A world that does not come to its prompt

One thing a world cannot be saved from is itself. A world in which something essential was redefined, and which was then saved, starts like that every time. When such a world does not get as far as its prompt, stop the machine and start it again. Every start is counted on the disk before anything else is done, and the count is taken away when the prompt is reached; a start that finds the count of the one before it still there passes the saved world over and makes a new one from the Lisp files. The report says so:

lisp: clara.image is passed over: the start before this one did not come to its prompt
...
world: the world that was saved did not come to its prompt at the start before this one.
world:   It is kept, and the next start tries it once more; this world is of the files and of /home/

The world that is made in its place has what you defined, from the text. The saved one is kept that first time, since one start that went wrong may have been anything, a machine that was switched off as it started. When the same saved world does not come to its prompt a second time, the world that was made takes its place on the disk:

world: the world that was saved did not come to its prompt a second time: this one takes its place
world: it is saved as it is now, and the next start is in it; (clara.system:report) says this again

And when the start after a world was passed over does not come to its prompt either, the text may be the reason, and the third start has neither: A file of your own.

{{spleen:What you define, kept as text}}

A saved world is quick to start and is only good for the system that saved it. So the system keeps your work a second way, as text, which every ClaraOS reads: in /home, on the disk that the machine started from. Two files there are what a world is made of beside the system's own.

/home/defined.lispis written by the system: every form that defines something, as you typed it at a prompt.
/home/init.lispis yours to write: whatever a new world should begin with.

Whenever a world is made anew, from the Lisp files and not from an image, the two are loaded into it, init.lisp first: after an upgrade, after the image was deleted, and when an image was passed over. A world that comes back from its image takes what is new of them: the forms that it does not have yet, which is what was defined after it was saved, on a machine that then stopped without saving, and what you wrote into a file since. A form that the world has is not evaluated a second time.

What is written down

> (defun area (width height) (* width height))
AREA
> (defun area (width height)
    ;; of a rectangle
    (* width height))
AREA
> (probe-file "/home/defined.lisp")
"/home/defined.lisp"

The file has the second area, comment and all, where the first one stood:

;;;; What was defined at the prompt, as it was typed. ClaraOS writes a form
;;;; here when it has been evaluated, in the place of an earlier one that
;;;; defined the same name, and loads this file into a world that is made
;;;; anew, after init.lisp. It is yours to read and to change.

...

(defun area (width height)
  ;; of a rectangle
  (* width height))
  • A form is written down when it was typed at a prompt, in any listener, on the serial port or in a window; when it stands by itself, and not inside a progn or a let; when it went well; and when its first word says that it defines something. That is a word of the language's own, defun, defmacro, defvar, defparameter, defstruct, defpackage, define-condition, defclass, defgeneric, defmethod; a macro of yours whose name begins with def; and anything whose name begins with define-, as clara.windows:define-application, and with it clara.windows:install-application. Any other call of a function is not written down, whatever the function is called: clara.windows:move-up is none, and what it did to the list is carried by an upgrade. A load is, since what a file defined is in none of the forms that were typed, unless it is one of the two files of /home that is loaded.
  • A form that defines a name again takes the place of the form that defined it before, so the file has every definition once, in the order in which each was first made. The methods of a generic function are so many definitions: each defmethod is in the file, and one takes the place of another when it is the same method, for the same classes and with the same word before its parameters.
  • Forms that were read in another package than the ones before them have a line (cl:in-package "NAME") before them.
  • What is not a definition is not written down. A variable that was changed after its defvar is in the file with the value that the defvar gives it, and a world that is made of the text alone has that one; an upgrade carries the value that it had come to as well. What a defvar did to get its value, it does again. And what Ctrl-E evaluated in Emma is in the file that Emma had open, and not here.
  • Nothing else that takes a definition back is written down: after (delete-package "PLAY") the forms that made the package, and what was defined in it, are still in the file. The file is text, and yours: read it, and take out of it what you no longer want, in Emma. What the system cannot read of it any more it leaves as it is, and goes on after it.

A file of your own

/home/init.lisp is not there until you write it. Whatever should happen in every new world goes into it: loading your own files, starting the window manager, anything that is not a definition typed at a prompt.

> (with-open-file (out "/home/init.lisp" :direction :output)
    (write-line "(defvar *motto* \"a world made anew, and mine\")" out))
"(defvar *motto* \"a world made anew, and mine\")"
> (list (clara.system:home) (clara.system:home-file "init.lisp"))
("/home/" "/home/init.lisp")

When a world is made, the report says what was loaded, and what was not:

home: /home/init.lisp is loaded, 1 form
home: /home/defined.lisp is loaded, 34 forms of it, and 1 was passed over:
home:   (defvar *window* (clara.windows:open-window "A picture" 200 120 :x 500 :y 400))
home:     there is no window manager to open a window with: (clara.windows:start) starts it
  • Each form is evaluated by itself. One that fails is passed over, with its beginning and the reason in the report, and the rest goes on: a form that a newer system no longer understands does not keep a world from being made.
  • A file gets a minute. One that has not come to its end by then is stopped where it is, and the machine goes on to its prompt. clara.system:*patience* is that time, in milliseconds.
  • A load of /home/init.lisp or /home/defined.lisp that stands in one of the two is passed over like a form that fails: the file would load itself without end. A file of yours anywhere else is loaded from init.lisp like from a prompt, with its name looked up on the disk that the machine started from.
  • After two starts in a row that did not come to a prompt, nothing of /home is loaded, in case that is the reason: the world is then the system's alone, the report says so, and the files are there to be put right. (clara.system:load-home) loads the two files into the world that it is typed in, the way a start does, and that world takes what is new of them from then on.

{{spleen:The network}}

A machine with a network card can fetch a file from another machine, open a connection to one, and take the connections that other machines open to it. The card is a VirtIO network card, which a machine under make run-* has unless it is told otherwise, and which UTM gives a machine by itself.

> (clara.net:station)
"52:54:00:12:34:56"
> (clara.net:address)
net: this machine is 10.0.2.15 on its network, 10.0.2.2 is the way out, 10.0.2.3 knows names
net: by IPv6 it is fec0::5054:ff:fe12:3456, fe80::2 is the way out
"10.0.2.15"

station is the card's own address on the wire, which it has from the start. The machine's address on the network is another matter: it asks the network for one (DHCP) the first time that something wants the network, and says what it was told. A machine that fetches nothing sends nothing. The second line is its address of the other kind, IPv6, on a network that has a router for it.

Under QEMU the network is one that QEMU makes up for the machine. The machine is 10.0.2.15 on it; 10.0.2.2 is the computer that QEMU runs on; and whatever that computer reaches, the machine reaches through it.

The address is the machine's for a time, which the network says with it, a day under QEMU. When half of that is over the machine asks whether it may keep the address, without being told to and without a word, so a machine that runs for a week is still on its network.

Is a machine there

> (< (clara.net:ping "10.0.2.2") 1000)
T

clara.net:ping asks a machine, by its name or its address, to send back what it is sent, and gives the milliseconds that the answer took, as far as the machine's clock tells them apart, which is to a hundredth of a second: 0 for a machine that is near. One that does not answer is asked again every second, and after ten seconds it is an error. The machine answers such a question itself: ping 10.0.2.15 from another machine on its network is answered.

Machines on the way say when they cannot hand a packet on, and the machine listens: a connection to a machine that cannot be reached ends at once with ... says that ... cannot be reached, and not after ten seconds of waiting.

Fetching a file

To have something to fetch, start a web server on the computer that QEMU runs on, in a directory with a file hello.txt in it: python3 -m http.server 8000. Then, on the machine:

> (clara.net:fetch-text "http://10.0.2.2:8000/hello.txt")
"hello from the other side
"
> (clara.net:resolve "claraos.org")

HTTPS

An address that begins with https:// is fetched over a connection that is kept closed: nobody on the way can read what goes over it or change it, and the machine at the other end has shown that it is the one that was asked for. That is TLS, version 1.3.

> (length (clara.net:fetch-text "https://claraos.org/"))
tls: this system trusts 118 certificates to say who a machine is
30027

The other side shows who it is with a certificate, which somebody signed who has a certificate too, and so on up to one that the system trusts. The machine looks at all of that before it asks for anything:

  • The certificate has to be for the name that was asked for, or for a name with a star that covers it: *.example.org is www.example.org, and not example.org.
  • It has to be good today, and so has every certificate above it. Today is what the machine's clock says, (get-universal-time).
  • The chain has to end in a certificate that the system trusts. Those are the ones of the authorities that sign for the web: the list that Mozilla keeps for its browser, as curl publishes it, in the file roots.pem of the system's directory. It is read the first time that something is fetched this way, which is when the line above is said. (clara.tls:roots) gives their names.
  • The other side has to sign the greeting with the key of its certificate, and both sides end the greeting with a word that only somebody who has heard the same greeting can make.

When one of these is not so, nothing is asked for and nothing is fetched, and the error says which it was.

(clara.tls:trust "/root.pem") adds the certificates of a file to the ones that the system trusts, and says whom they are for; the file is as such files are written, with -----BEGIN CERTIFICATE----- before each. The text of such a file, as a string, does as well as its name. That is for a server of your own, whose certificate no authority signed. A world that is saved keeps what was added; a world that is made again, after an upgrade, does not, so a line in /home/init.lisp is where it belongs.

Two things have to be there, and under make run-* both are:

  • A device that makes numbers which nobody can guess: the keys of a connection are made of them. It is a VirtIO device, -device virtio-rng-pci under QEMU, and RNG= gives a machine without one. (clara.random:below 6) is a number from 0 to 5 from it, and (clara.random:bytes address count) writes that many such bytes into memory.
  • The time of day, which the system has from the firmware's clock as it starts.
> (< (clara.random:below 6) 6)
T
> (> (get-universal-time) 3976214400)
T

What is not there: versions of TLS before 1.3; any cipher but AES-128-GCM, which every server of TLS 1.3 has to have, and any exchange of keys but X25519, which nearly every one has; a certificate of the machine's own, for a server that wants one; and asking whether a certificate has been taken back since it was signed.

IPv6

An address of IPv6 is eight numbers in base sixteen with colons between them, and two colons where zeroes are left out. A machine has two of them on a network whose router speaks IPv6: one that it makes for itself, which begins with fe80 and goes no further than its own network, and one on the network that the router names. It asks the routers when something first wants the network, as it asks for its other address, and both kinds are the machine's from then on.

> (clara.net:addresses)
("10.0.2.15" "fec0::5054:ff:fe12:3456" "fe80::5054:ff:fe12:3456")
> (< (clara.net:ping "fec0::2") 1000)
T
  • Everything in this chapter goes over either kind: ping, fetch, connect and serve take such an address where they take the other, and a port that takes connections takes them by both.
  • A name can have addresses of both kinds, and the machine asks for the kinds that it has itself. It goes by IPv6 first when its own address of that kind is one of the Internet's, which begin with 2 or 3, and by IPv4 first otherwise; when nothing takes the connection at the first address, the next is tried. clara.net:resolve gives the one that comes first.
  • Under QEMU the machine's addresses of IPv6 are on the network that QEMU makes up: fec0::2 is the computer that QEMU runs on, and what lies beyond is reached by IPv6 only when that computer has IPv6 itself. So a machine there goes by IPv4 where it can, as it always did.
  • (setq clara.net:*ipv6* nil), before anything has wanted the network, and the machine does not speak IPv6 at all.
  • On a network where nothing hands out addresses of IPv4 and a router speaks IPv6, the machine says so and gets by with what the router gave it.

What is not there: the machine does not ask whether another machine has made the same address; the second half of its addresses is its card's address, wherever it is; it takes its addresses from the routers' word alone, and not from a DHCP server for IPv6; and packets that were taken apart on the way are dropped.

... is not on this machine's network, and no router has said that it is a way outThe same, for a machine that has an address and no way out.

A machine that listens

The machine takes the connections that other machines open to one of its ports, once it is told to, and hands each to a function of yours, in a thread of its own. The function is given a stream. read-line gives what the other side says, a line at a time, and NIL when the other side is done; what is written to the stream goes to the other side. When the function returns, the connection is over.

> (defun shout (stream)
    (loop
      (let ((line (read-line stream nil)))
        (unless line (return))
        (write-line (string-upcase line) stream))))
SHOUT
> (clara.net:serve 7 'shout)
7
> (clara.net:with-connection (stream "127.0.0.1" 7)
    (write-line "is anybody there" stream)
    (write-line "and again" stream)
    (list (read-line stream) (read-line stream)))
("IS ANYBODY THERE" "AND AGAIN")
> (clara.net:stop-serving 7)
T
  • clara.net:serve takes a port and a function, or the name of one, which lets you define the function anew while connections are taken. :most says how many connections are taken at once, eight when nothing is said; a machine that asks for one more is told that there is none. Nothing is taken at any port that serve was not told.
  • (clara.net:serving) lists the ports, each as (port taken open trouble): how many connections were taken there, how many of them are open, and what the function last ended in when that was an error, which is not printed anywhere else. clara.net:stop-serving ends it for a port, and the connections that are open with it.
  • clara.net:connect opens a connection to a port of another machine, by its name or its address, and gives the same kind of stream, which is yours to close. clara.net:with-connection does that for you, whichever way its body is left.
  • A line ends with a newline, and a carriage return before it, which the Internet's protocols have there, is no part of the line. Text is UTF-8. What the other side says last without ending the line is a line too. A line of more than 64 KiB is an error.
  • read-line waits as long as clara.net:*patience* says, ten seconds, and then it is an error, which ends a function that does not handle it, and with it the connection. A function that is to wait longer for somebody at a keyboard binds the variable: (let ((clara.net:*patience* 600000)) ...).
  • 127.0.0.1 is the machine itself, to itself, and so is its own address: nothing goes onto the network for either, which is how a function is tried before another machine is there.
  • A world that is saved while it takes connections takes them again when it is started, and says so. A world that is made again, after an upgrade, does not: a line in /home/init.lisp is where serve belongs then.

Under QEMU, the network that QEMU makes up lets nothing in. FORWARD=8007:7 make run-aarch64 has QEMU hand on what connects to the port 8007 of your computer, from that computer only, to the port 7 of the machine: nc 127.0.0.1 8007 there, and what you type comes back in capitals. In UTM the machine is on a network that it shares with the Mac, and is reached at its own address.

Nothing keeps such a connection closed: what a function says and hears there is in the open, for anybody on the way to read and to change. The TLS of this system is the half that asks, for fetching. That is why there is no web server here.

{{spleen:A newer ClaraOS}}

A system is one build of ClaraOS: its two kernels and its Lisp files. On a disk it is a directory, /clara and then its name, with a list in it of what it is made of. A newer ClaraOS is another such directory, and the system that is running puts it on its own disk, beside itself: that is an upgrade. The files that you wrote stay where they are, and nothing else on the disk is touched.

Under QEMU

There is nothing to do. When the build is another system than the one on the machine's disk, make run-aarch64 says so and gives the machine the build as a second disk, marked as one to take at once:

tools/run.sh: build/disk-aarch64.img holds ClaraOS 0.0.25-8f3a1c2e, and the build is {{version}}-41d0c97b: the machine is given the build
    as a second disk, takes it, and starts again by itself to try it.

The machine starts as the system that it was, takes the newer one, starts again, and comes to its prompt as the newer one, a few seconds later than usual. Its report tells the story as it goes, in the lines that begin with system:.

In UTM, or on any machine

  1. make image makes the newer build/claraos.img.
  2. Stop the machine. Give it that image as a second drive, with the interface VirtIO, after the drive that it starts from.
  3. Start it, and say: 
    > (clara.system:upgrade)
system: {{version}}-41d0c97b is on the disk, and is tried at the next start
clara: the world is saved
clara: starting the machine again
  4. When the newer system has come to its prompt, the second drive has done its work, and can be taken out again the next time the machine is stopped.

(clara.system:upgrade :start-again nil) takes the system and leaves the machine running; the newer system is tried whenever the machine is next started. :from names the volume to take it from, one of (clara.fat:volumes), where the first disk that holds another system is taken otherwise. From a disk it need not be a newer one: any ClaraOS that is not the one that runs is taken, an older one as well.

Over the network

A newer ClaraOS can also be fetched. The newest one is published at https://claraos.org/releases/: a directory on the website that holds a system as a disk does, and beside the list of its files a signature of that list. When no other disk of the machine holds a system, (clara.system:upgrade) looks there, and says so before it does:

> (clara.system:upgrade)
system: no other disk of this machine holds another ClaraOS, so the newest one is looked for at https://claraos.org/releases/
system: {{version}}-41d0c97b is published at https://claraos.org/releases/, and signed with the key that this system has: its files are fetched
system: {{version}}-41d0c97b is on the disk, and is tried at the next start
clara: the world is saved
clara: starting the machine again

From there on it is the upgrade from a disk: the newer system is tried at the next start, and the old one is there until the new one has come to its prompt. A machine that has the newest ClaraOS already is told so, and has fetched one line.

  • The machine asks there when it is told to, and at no other time. (clara.system:newest) asks which system is the newest that is published, and fetches nothing else.
  • What is published there is the system of the newest commit on the main branch of ClaraOS's repository: it is built and signed there each time a change is merged, and takes the place of the one before.
  • A disk goes first: when another disk of the machine holds a system, that one is taken and nothing is asked of the network.
  • It is fetched by HTTPS, and from no address that begins otherwise: nobody on the way reads what the machine fetches, or tells it that an older release is the newest.
  • And nothing is believed for having arrived. The list of the system's files is held against its signature, with the public half of the key that the release was signed with, which the system has in clara.system:*release-key*; and every file is held against the list, by its length and its SHA-512. What fails either is not taken, and the machine starts as it did before. So a release is its publisher's whatever web server hands it out.
  • Only a newer system is taken: one whose version is higher than that of the system that runs. :any t takes whatever is published there, an older one as well.
  • The system has the place in clara.system:*releases* and the key in clara.system:*release-key*. Another place is named with :from: (clara.system:upgrade :from "https://...") takes the newest system that is published at that address, when it is signed with the key that the system has, and (clara.system:newest "https://...") says which one that is.

To publish a system yourself: make a key, once, and lay the system out as a release, on the computer that builds it.

python3 tools/release.py key my.key          # once: the secret half goes into my.key, the public half is printed
make
python3 tools/release.py make build/esp/clara/{{version}}-41d0c97b releases my.key

Then put the directory releases where a web server hands it out by HTTPS. With a web server whose certificate an authority signed, that is all, and on the machine, with the 64 digits that the first line printed:

> (setq clara.system:*release-key* "8c33f9eb730e625013b19d5ea0646d3dd45fa3a03e5977912319a1cee6529fbe")
> (clara.system:upgrade :from "https://example.org/releases/")

A system that is to look at your place by itself has the address and those digits where lisp/system.lisp defines the two variables, before it is built. make release KEY=my.key RELEASES=releases then lays the release out, and refuses a key whose public half is not the one in that file.

To try it from your own computer, which no authority signs for, the build has a web server and makes the certificates for it:

python3 tools/certs.py certs releases.test    # a root of your own, and a certificate for that name
python3 tools/serve.py releases ports certs   # the file "ports" gets two numbers: a port for names, and the one for HTTPS

The machine has to know the name and to trust the root. Put certs/root.pem on a disk of your own, and with the two numbers, here 8053 and 8443:

> (setq clara.net:*name-server* "10.0.2.2" clara.net:*name-port* 8053)
> (let ((clara.fat:*volume* (second (clara.fat:volumes)))) (clara.tls:trust "/root.pem"))
> (clara.system:upgrade :from "https://releases.test:8443/")

Whoever has my.key can publish a ClaraOS that every machine with that public half takes for the real one. It belongs to nobody but the one who publishes.

What happens at the next start

The newer system is tried before it takes the old one's place. The firmware still starts the old kernel, which sees that a system is waiting, and starts that system's kernel in place of itself, once. The report of that start begins like any other and ends like this:

system: this is ClaraOS {{version}}-41d0c97b, on trial: the system before it is still in place
system: {{version}}-41d0c97b has come to its prompt, and is the system of this machine from here on

With the second line the newer system has put its kernels where the firmware looks for them and taken the old system's directory away. Until then the old system is whole, and is what the machine starts as: when the newer one stops on the way, with a report that begins with panic:, or stands still, stop the machine and start it again. It comes up as it was before the upgrade, in the world that was saved then, and says:

system: {{version}}-41d0c97b was tried and did not come to its prompt: this is still 0.0.25-8f3a1c2e

A system that failed like that is not taken a second time by itself, however often make run-aarch64 offers it; (clara.system:upgrade) tries it again when you ask. An upgrade that is cut short while the files are still being copied changes nothing: the machine starts as the old system, and the upgrade can be asked for again.

What comes across

  • Every file that you wrote, wherever it is on the disk. The upgrade writes into /clara and /EFI and nowhere else.
  • What you defined at a prompt, as text: the newer system loads /home/init.lisp and /home/defined.lisp into the world that it makes.
  • What your variables had come to, as far as that is text: numbers, characters, strings, symbols, and lists of those. The old system writes those values down as it leaves, and the new one gives them to the variables once the text has defined them.
  • The window manager: it is started when it was running, with one REPL window, and a form of your text that opens a window opens it.
  • The order of the list under Applications, when you moved a line of it: the names stand as they stood. An application or a command that is new with the system stands behind the name that it is defined after, and an application that the newer system has under another name stands where it stood under its old one, as Jaid does, which was Files until 0.0.54.
  • The time zone that the machine was told, clara:*time-zone*: the clock tells the time of the same place.
  • What else you set of the system's own, in Settings or at a prompt, where it is no longer as the system came: the letters of the bar and of the windows of text, the clock, how loud the machine is, and how much a REPL keeps. Those are variables of the system's, clara.windows:*font* for one, and the report names them among your own. A value that is no text, a clock that is a function and not the name of one, does not come across, which the report says too.
  • Not the world itself. A world belongs to the system that saved it, so the newer system makes one of its own files, and saves it without being asked: the next start is in it. What is no text is not in it: a function that no form of the text defines, a thread, a lock, a list that leads back into itself. A variable that held such a thing has what its form makes anew.

The newer system says which is which as it starts, by name:

home: /home/defined.lisp is loaded, 35 forms
world: 3 variables have the values that they had come to in the world before:
world:   *ASKED*, *JOBS*, *THREADS*
world: 8 variables held what is no text, and are as their forms make them here:
world:   *ADD*, *BELL*, *CANVAS*, *HELD*, *SEEN*, *SVREF*, *WAITER*, *WINDOW*
world: 3 names that the world before had are not defined in this one:
world:   *SPINNER* (a variable), HI, NOT-WRITTEN-DOWN
world: it is saved as it is now, and the next start is in it; (clara.system:report) says this again

The last of the three lists is what did not come across: names that the old world had, in COMMON-LISP-USER and in the packages that you made, and that nothing in the text defines. They were defined inside another form, by a file that was loaded from inside one, or in Emma. (clara.system:report) says all of it again, at any later time, with every name, where the report of a start says the first few lines of a long list.

The disk needs room for two systems while the newer one is tried, some four mebibytes beside what is there. When it has less, the upgrade says so and does nothing.

{{spleen:Threads}}

A thread is a function that runs beside the others. The prompt is one thread, the listener, and each keyboard and pointer has one. The names are those that Bordeaux Threads made usual, in the package CLARA.

> (clara:current-thread)
#<THREAD "listener">
> (clara:join-thread (clara:make-thread (lambda () (* 6 7)) :name "worker"))
42
> (defvar *jobs* 0)
*JOBS*
> (let ((lock (clara:make-lock)))
    (mapc #'clara:join-thread
          (mapcar (lambda (n) (clara:make-thread (lambda () (clara:with-lock-held (lock) (incf *jobs* n)))))
                  '(1 2 3)))
    *jobs*)
6
> (let ((bell (clara:make-event "bell")))
    (clara:make-thread (lambda () (sleep 1) (clara:signal-event bell)))
    (clara:wait-event bell))
T
> (clara:join-thread (clara:make-thread (lambda () (car 5)) :name "faulty"))
error in #<THREAD "faulty">: CAR wants a list, and 5 is not one
error: the thread #<THREAD "faulty"> ended with an error: CAR wants a list, and 5 is not one
> (defvar *spinner* (clara:make-thread (lambda () (do () (nil))) :name "spinner"))
*SPINNER*
> (clara:thread-alive-p *spinner*)
T
> (clara:destroy-thread *spinner*)
T
> (clara:join-thread *spinner*)
error: the thread #<THREAD "spinner"> was stopped
  • clara:make-thread starts a function of no arguments in a thread of its own, and clara:join-thread waits for it and gives what the function gave.
  • A thread that ends with an error says so on the console, and the error is what join-thread then reports. The other threads go on.
  • A lock is held by one thread at a time. clara:with-lock-held takes it for the forms inside and gives it back whichever way they end.
  • An event counts how often it was signalled. clara:wait-event waits until it has been, and takes one off the count. With a number of milliseconds as its second argument it waits no longer than that, and gives NIL when the time ran out.
  • (sleep 2) waits two seconds. The other threads run meanwhile.
  • clara:destroy-thread tells a thread to stop, which it does at its next step, cleaning up on its way out.
  • clara:interrupt-thread is Ctrl-C for one thread: what it computes, or waits for, ends with the condition clara:keyboard-interrupt, which the thread can handle. A REPL window does this to its own thread when Ctrl-C is typed in it.

The threads take turns, a hundredth of a second each. One of them at a time is evaluating, on the one processor that the system uses, so threads keep the machine answering while something waits, and do not make a computation faster. Each thread has its own bindings of the special variables: one that it binds with let is bound for it alone. A thread costs about a mebibyte and a half of memory.

T

The last of these puts the picture on the screen, its corner 600 pixels across and 40 down. Until then nothing of it could be seen.

  • clara.draw:allocate-surface makes a surface of so many pixels across and down, all of them black. clara.draw:surface-width and clara.draw:surface-height say how large one is.
  • clara.draw:color makes a colour of its red, its green and its blue, each from 0 to 255. What it gives is a pixel as this machine's screen has them, a number, and that is what everything that draws takes.
  • clara.draw:fill-rectangle takes a surface, the place of the rectangle's upper left corner, its width and its height, and a colour. clara.draw:draw-rectangle takes the same and draws the outline only, a pixel thick. A line along a row or a column is a rectangle that is one pixel high or wide.
  • clara.draw:draw-text draws a string in the console's font, in which every character is 8 pixels wide and 16 high, with the upper left corner of the first one at the place given. With one more colour after the first, the cells of the characters are filled with it, and without it only the characters themselves are drawn, over what was there. clara.draw:text-width says how wide a string will be. Both take a font after that, for letters of other shapes and sizes.

What lies outside

Nothing is drawn outside a surface, and it is no mistake to try: a rectangle that lies half outside is drawn half. Each function that draws gives T when it drew something and NIL when all of it lay outside. clara.draw:with-clip keeps the drawing of the forms inside it to a part of the surface.

> (clara.draw:fill-rectangle *paper* 150 70 100 100 *red*)
T
> (clara.draw:fill-rectangle *paper* 200 0 10 10 *red*)
NIL
> (clara.draw:with-clip (*paper* 0 0 96 80)
    (clara.draw:draw-text *paper* 72 48 "cut off" *red*))
T
> (list (= (clara.draw:pixel *paper* 30 30) *red*)
        (clara.draw:pixel *paper* 100 56) (clara.draw:pixel *paper* 160 0))
(T 1973038 NIL)

Of "cut off" the first three characters were drawn, up to the pixel 96 across. clara.draw:pixel gives the pixel at a place, or NIL when the surface has none there.

Showing what has changed

A surface remembers which parts of it were drawn on, as a few rectangles: its damage. clara.draw:show copies those parts to the screen and forgets them, so what goes to the screen is what has changed since the last time, however much or little that is. Here it is the three characters and the corner that were drawn since the picture was first shown.

> (clara.draw:damage *paper*)
((72 48 24 16) (150 70 10 10))
> (clara.draw:show *paper* 600 40)
T
> (clara.draw:show *paper* 600 40)
NIL
> (clara.draw:copy-rectangle *paper* 20 20 40 30 *paper* 110 44)
T
> (defvar *arrow*
    (vector #b1000000 #b1100000 #b1110000 #b1111000
            #b1111100 #b1100000 #b0010000))
*ARROW*
> (clara.draw:draw-bitmap *paper* 4 2 *arrow* 7 *ink*)
T
> (clara.draw:damage *paper*)

> (clara.draw:show *paper* 600 40)

  • A rectangle of damage is a list: how far across and down it begins, how wide it is and how high. clara.draw:take-damage gives the same list and leaves the surface without any, and clara.draw:add-damage counts a part as drawn on, to have it shown again.
  • clara.draw:copy-rectangle copies a part of one surface to a place on another, or on the same one: the surface it comes from, the corner of the part, its width and height, then the surface it goes to and the corner there.
  • clara.draw:draw-bitmap draws a picture of one bit to the pixel. The picture is a vector of its rows from the top, each a number whose bits are the pixels of the row, and after it comes how many pixels wide it is. Where a bit is 1 the pixel takes the colour. With one more colour after it, the pixels whose bit is 0 take that; without, they stay as they were.
  • (clara.draw:screen) is the screen as a surface, or NIL on a machine without one. Whatever is drawn on it shows at once, and it keeps no damage.

The console writes on the same screen. A picture that is shown there lies over the text, the lines that are written after it go over the picture where they meet it, and when the text moves up a line the picture moves up with it. So a picture stays where it was put only as long as nothing is printed. A picture that is to stay belongs in a window, and while the window manager runs the screen is its own: what is shown there directly is painted over the next time a window moves.

Memory

A surface takes four bytes for every pixel, 1875 KiB for one as large as a screen of 800 by 600, and that memory is not the heap's: nothing gives it back when the surface is no longer used. clara.draw:free-surface does, and after it the surface cannot be drawn on.

> (clara.draw:free-surface *paper*)
NIL
> (clara.draw:draw-text *paper* 0 0 "gone" *red*)
error: this surface was freed

A world that is saved keeps its surfaces and not their pixels. After the machine has started again, a surface from before is refused with this surface is of a machine that was switched off: make a new one, and draw the picture again. A function that draws it comes back with the world.

There are no lines but those along a row or a column, and no circles. A colour covers what is under it, except where a picture in shades says how much of it a pixel takes, which is how the letters of a font are drawn.

{{spleen:Fonts}}

The console's letters are pictures, 8 pixels wide and 16 high, and there is one of each. A font of outlines has the shape of every letter instead, as lines and curves, and draws it at any size. Where the edge of a letter passes through a pixel, the pixel takes as much of the colour of the text as the letter covers of it, so a stroke that slants or bends comes out smooth. Three families of letters come with the system: Sans; Mono, in which every character is as wide as every other; and Serif, whose letters have feet. Each has an upright, a bold, an italic and a bold italic. A fourth, Emoji, is pictures, and is where the emoji of every text come from. Sans and Mono are the Go fonts, which Bigelow & Holmes drew for the Go project, and Serif is Charter, which Matthew Carter drew for Bitstream. The functions are in the package CLARA.TYPE, and what draws text takes a font as its last argument.

> (defvar *sans* (clara.type:font "Sans" 24))
*SANS*
> (list (clara.type:font-height *sans*) (clara.type:font-ascent *sans*)
        (clara.type:font-descent *sans*))
(29 23 6)
> (clara.draw:text-width "Hello, world" *sans*)
127
> (defvar *page* (clara.draw:allocate-surface 300 120))
*PAGE*
> (clara.draw:fill-rectangle *page* 0 0 300 120 (clara.draw:color 30 27 46))
T
> (clara.draw:draw-text *page* 10 8 "Hello, world" *ink* nil *sans*)
T
> (clara.draw:draw-text *page* 10 46 "bold and italic" *ink* nil
                        (clara.type:font "Sans" 18 :bold t :italic t))
T
> (clara.draw:draw-text *page* 10 78 "(defun underlined ())" *red* nil
                        (clara.type:font "Mono" 14 :underline t))
T
> (clara.draw:show *page* 460 140)
T
  • clara.type:font takes the name of a family and a size, and gives a font: the same one every time that the same is asked for. The size is how many pixels the font's em has, from 4 to 400, which is somewhat less than a line of it is high: at 24 a line of Sans takes 29. :bold t and :italic t pick the family's bold and italic, and with :underline t or :strike t a line is drawn under the text or through it. clara.type:font-name and clara.type:font-size say what a font was asked for by, and clara.type:font-p whether something is one.
  • clara.type:font-height is how far it is from the top of one line of text to the top of the next. clara.type:font-ascent is how far below the top of a line the letters stand, and clara.type:font-descent how far below that the tails of letters like g reach.
  • clara.draw:draw-text with a font draws the string with the upper left corner of its line at the place given, and clara.draw:text-width with a font says how wide the string will be. The argument before the font is the colour that the line is filled with first, or NIL to draw the letters over what is there.
  • A character that the font has no shape for is drawn as the font's own sign for that, a box, unless it is an emoji, which is its picture. Sans and Mono have the letters of Latin, Greek and Cyrillic writing, and Serif the Latin letters of the languages of western Europe.

Families and files

> (clara.type:families)
("Sans" "Mono" "Serif" "Emoji")
> (clara.type:font "Gothic" 24)
error: Gothic is not a font that can be had here: there is no file Gothic
> (clara.type:font "Sans" 2)
error: the size of a font is a whole number of pixels from 4 to 400, and 2 is not

A name that no family has is taken for the name of a file, so a font file of your own can be drawn in from where it lies, and clara.type:define-family gives a family of such files a name:

> (defvar *mine* (clara.type:font "/home/fonts/Mine.ttf" 30))
*MINE*
> (clara.type:define-family "Mine" "/home/fonts/Mine.ttf"
                            :bold "/home/fonts/Mine-Bold.ttf")
"Mine"
> (clara.draw:text-width "Hello" (clara.type:font "Mine" 30 :bold t))
84

The files that are read are TrueType's, whose names usually end in .ttf. A font file of the other common kind, most of those whose names end in .otf, is refused, in words that say so. A family need not have all four files: :italic and :bold-italic name the other two, and where one is missing the nearest that is there stands in. A file is read when a font is first made of it and stays in memory. (clara.type:forget) lets go of the files that were read from a disk, after which a file that has changed there is read anew.

Nothing fits the letters to the pixels, so at the smallest sizes they are soft where the console's are sharp; and no two letters are moved together where their shapes would allow it, as a careful printer would.

Text in cells

A line of text has each letter where the one before it ends, as wide as the letter is. A window of text is laid out the other way: a grid of cells of one size with a character in each, so that a row is so many characters whatever they are, and a place in the text is a cell. clara.draw:draw-cells draws a string that way, and clara.draw:cell-width and clara.draw:cell-height say how large a cell is.

> (list (clara.draw:cell-width) (clara.draw:cell-height))
(8 16)
> (defvar *mono* (clara.type:font "Mono" 16))
*MONO*
> (list (clara.draw:cell-width *mono*) (clara.draw:cell-height *mono*))
(10 20)
> (clara.draw:cell-width (clara.type:font "Serif" 16))
16
> (clara.draw:draw-cells *page* 150 78 "in cells" *ink* *red* *mono*)
T
  • Without a font the cells are the console's, 8 by 16, with the console's letters in them. With one, a cell is as high as a line of the font, and as wide as the widest of the characters that are typed, the ones from the space to ~. In Mono that is every character's width, and its words stand as they do in a line of text. In Sans and Serif, whose letters differ, a cell is as wide as an M or a W, and an i has the same room: the words come out spaced.
  • clara.draw:draw-cells takes what clara.draw:draw-text takes: a surface, the place of the first cell's upper left corner, the string, the colour of the letters, the colour that the cells are filled with first, or NIL to leave them as they are, and the font, or none. A character stands in the middle of its cell, and what of it would lie outside the cell is not drawn, the tip of a leaning letter for one: so one cell can be drawn again and the cells beside it stay as they are.

The windows of the REPL, of Emma, Jaid and Parker are such grids, and which font they are in is yours to say.

Emoji

An emoji is a character like any other, in a string and in a file, and what is drawn of it is a picture in colours of its own. The pictures are the fourth family, Emoji: Twemoji, the emoji that Twitter drew, as the font that Mozilla made of them, some 3,700 pictures, which are the emoji of Unicode 14. A text in any font has its emoji from there, at the font's size, and so has a text in the console's letters, where an emoji is as wide as two of them.

> (defvar *rocket* (string (code-char 128640)))
*ROCKET*
> (list (clara.draw:emoji-p (char *rocket* 0)) (char-code #\U+1F680))
(T 128640)
> (list (clara.draw:text-width *rocket* *sans*) (clara.draw:text-width *rocket*))
(24 16)
> (clara.draw:draw-text *page* 200 8 *rocket* *ink* nil *sans*)
T
> (defvar *flag* (format nil "~a~a" (code-char 127482) (code-char 127475)))
*FLAG*
> (list (length *flag*) (clara.draw:text-width *flag* *sans*))
(2 24)
> (length (clara.draw:in-cells (format nil "a~ab" *rocket*)))
4
> (clara.draw:draw-cells *page* 150 98
                         (clara.draw:in-cells (format nil "a~ab" *rocket*))
                         *ink* *red* *mono*)
T
> (string= (clara.draw:from-cells (clara.draw:in-cells *flag*)) *flag*)
T
> (clara.type:font-height (clara.type:font "Emoji" 64))
78
  • clara.draw:emoji-p says whether a character is an emoji. Which are is Unicode's to say: 1,424 characters, from U+203C on. The digits, # and *, and the signs for a copyright and a registered mark are on Unicode's list too and not on this one: they are letters wherever they stand by themselves.
  • In a line of text, characters that the font of the pictures has one picture for between them are that picture. The two letters of a country are its flag, as the two of *flag* are the flag of the United Nations; a hand or a face and one of the five colours of skin are the hand in that colour; and people with the character that joins them, U+200D, between them are a family. A character that only says how another is to be shown shows nothing by itself: the joiner, and U+FE0F, which says that the character before it is meant as a picture.
  • A character that a font of letters has a shape for is the font's: the heart of a suit of cards in Sans is the one that Sans has, in the colour of the text, unless U+FE0F follows it. In the console's letters, which have none of them, every emoji is its picture.
  • In cells an emoji takes two, its own and the one after it, and its picture stands in the middle of them. clara.draw:in-cells makes of a text the string that clara.draw:draw-cells draws so: after every emoji it has the character clara.draw:+taken+, which stands for the second cell and shows nothing, so that a place in the string is still a cell, and it leaves out the characters that show nothing by themselves. clara.draw:from-cells gives the text of such a string. An emoji without clara.draw:+taken+ after it is drawn in one cell, as a box. Nothing is joined in cells: a flag there is its two letters, a picture each.
  • That is what a terminal does with what is written to it and typed in it, the REPL's among them. The titles of the windows, the bar and the launcher's list are lines of text, and so is a page in Ares. Emma, Jaid, Parker and Settings show a box for an emoji, and keep it as it is; so does the screen before the window manager has it.
  • No key types an emoji. (code-char 128640) is one, #\U+1F680 is the same one written as a character, and format puts either into a string. What is typed at the serial port can be any character, and Ctrl-V types what was copied from a window.
  • (clara.type:font "Emoji" 64) is the family as a font, for a picture at a size of its own. clara.type:define-family can give the name to another file of pictures: one whose pictures are layers of one colour each, or plain outlines, which are drawn in the colour of the text. An emoji that the file has no picture of is a box, as the ones are that are newer than the file.

Shades

A number says how much of the colour its pixel takes: 0 leaves the pixel as it was, 255 makes it the colour, and what is between leaves it between the two.

{{spleen:Windows}}

The window manager puts windows on the screen: each is a surface that a program draws on, in a frame with its title. It takes the screen from the console, which goes on with the serial port, where the prompt stays as it was.

> (clara.windows:start)
T
> (mapcar #'clara.windows:window-title (clara.windows:windows))
("REPL")

The screen now shows a bar along its top, with Applications at its left-hand end and, at the right, the system's name and version and the day and the time; a window named REPL, with a prompt in it; and the pointer. It is worked like this:

A click on a windowbrings it to the top. The window on top has the focus: its frame is lit, and what is typed goes to it.
The title of a windowis where to take hold of it: press the button there, move, and let go.
The x at the end of the titlecloses the window, and ends the program in it.
Applicationslists the applications there are, and under a line Restart and Shut Down. A click on a name starts the application, or does to the machine what the name says, and a click anywhere else puts the list away.
Alt and Tabbrings the lowest window to the top, and so each window in its turn.

What the bar, the list and the titles say is written in a font, Sans at 13 pixels. clara.windows:*font* says which: a list of a name, a size and whatever else clara.type:font takes, (list "Sans" 13 :bold t) for bold ones; or a font; or NIL for the console's letters. The window manager reads it as it starts, and again when it is told that the variable holds something else: (clara.windows:redraw) puts the whole screen together again in the letters that the variable says by then, and the windows stay as they are. The bar and the titles keep their height, which a font of up to 16 pixels fits.

> (setq clara.windows:*font* (list "Serif" 14))
("Serif" 14)
> (clara.windows:redraw)
T
> (setq clara.windows:*font* (list "Sans" 13))
("Sans" 13)
> (clara.windows:redraw)
T

The variable stays with a world that is saved and comes across to the world that a newer system makes, and Settings has two lines for it. Letters that cannot be had, a family that the machine has no file of, are said on the serial port, and the console's stand in.

A REPL window is a prompt like the first one, with the same keys, except that Ctrl-D closes the window and Ctrl-C stops what that window is evaluating. Every prompt is in the one world: what is defined in a window is defined at the serial port and in the next window. Each has a thread of its own, so one can compute while you type in another, and each is in a package of its own choosing.

What a REPL window has said is not gone when it leaves the window by its top. Page Up shows the rows before the ones that the window shows, a window's worth less one, so that the row that was first is now last, and so on as far back as the first row that the window ever had; Page Down shows the rows after them, down to the last. What is written meanwhile is written, and the window goes on showing what it showed, so a form can be evaluated and what it prints looked at while it goes by. Any other key brings the last rows back, where the prompt is and where the key is typed. The window keeps the newest 100000 rows that have left it, for as long as it is open.

What was typed at a REPL's prompt is not gone either, once Enter has ended the line. The arrow up puts the line that was read last at the prompt again, as it was typed and in its colours, to be read once more with Enter, or changed first. The arrow up again brings the line before that one, and so on as far back as the oldest; the arrow down goes the other way, down to the line that you were typing when you pressed the first arrow, which is as you left it. So is every line that the arrows pass: what you type into a line that came back stays in it while you look at the others, until Enter reads one of them. That one is the newest line from then on, and the lines that were remembered are as they were.

The arrow upthe line that was typed before the one at the prompt.
The arrow downthe line that was typed after it, and in the end the one that you were typing.

The lines come back a line at a time: a form that was typed as three lines is three of them, the last one first. There is one list of them for all the REPL windows, as there is one world: a line that was typed in one window comes back in the next, and in a window that is opened when the first is long closed. A line is not remembered a second time right after itself, and one with nothing in it not at all. The newest 1000 are kept, clara.terminal:*lines-kept*, and they stay with a world that is saved; the world that a newer system makes begins without them. What is typed at the first prompt and on the serial port is not among them.

It needs a keyboard and a pointer that the system has drivers for. make run-aarch64 gives the machine both, and so does UTM on Apple silicon. With a keyboard alone, the REPL window still takes what is typed, and the functions below do what the pointer would.

The clock

The right-hand end of the bar says the day and the time, Thu Nov 26 00:52: the day of the week, the month and the day of it, and then the hour, of twenty-four, and the minute. It is right again within a second of every minute that ends. The time is the machine's own, (get-universal-time): what the firmware's clock said as the machine started, and the time that the machine has counted since. A machine whose firmware has no clock has none in its bar, and a screen that is too narrow for both the clock and the system's name has the clock.

Under QEMU the firmware's clock keeps Greenwich's time, and nothing tells a machine where it stands. clara:*time-zone* says it: how many hours the place is behind Greenwich, which is how Common Lisp counts a time zone, so 5 for New York in winter and 4 in summer, 8 for San Francisco, -1 for Berlin and -9 for Tokyo. It is 0 until you say otherwise, and the clock goes by it within a second.

> (setq clara:*time-zone* 5)
5
> (clara.windows:day-and-time 3976214400)
"Wed Dec 31 19:00"
> (multiple-value-list (decode-universal-time 3976214400))
(0 0 19 31 12 2025 2 NIL 5)
> (setq clara:*time-zone* 0)
0
> (clara.windows:day-and-time 3976214400)
"Thu Jan 1 00:00"

3976214400 is the moment at which 2026 began in Greenwich, counted as (get-universal-time) counts. (decode-universal-time time) takes such a time apart, into nine values: the second, the minute, the hour, the day of the month, the month, the year, the day of the week, which is 0 for a Monday and 6 for a Sunday, NIL, where Common Lisp says whether daylight saving time is in force, and the time zone. A second argument is the time zone to go by in place of the variable's. (get-decoded-time) gives the nine for this moment.

  • A time zone is a whole number of hours, from -24 to 24, since there are no fractions: a place that is half an hour off the others cannot be said yet.
  • Nothing here knows of daylight saving time. The number is the same in summer and in winter until you change it.
  • It stays with a world that is saved, and it comes across to the world that a newer system makes. A world that is made anew for another reason, after the image was deleted for one, begins in Greenwich: a line in /home/init.lisp says it for good.
  • The machine counts the time from when it started, and counts nothing while it stands still: a machine that was paused has a clock that is behind by that much, until it is started again.

What the clock says is what a function makes of the time. clara.windows:*clock* holds that function, or its name, which is clara.windows:day-and-time as the system comes. Another function of a time that gives a string is another clock: this one says 12:52 AM.

(setq clara.windows:*clock*
      (lambda (time)
        (multiple-value-bind (second minute hour) (decode-universal-time time)
          (format nil "~D:~2,'0D ~A" (1+ (mod (+ hour 11) 12)) minute
                  (if (< hour 12) "AM" "PM")))))

With NIL there the bar has no clock. The function is asked every second, in a thread of the window manager's own that is named clock, and the bar is drawn again when it says something else than before: another clock shows within a second, and one that says the seconds counts them. A function that fails leaves the bar without a clock, and the serial port says why, once, in a line that begins with windows: the bar has no clock. What the variable holds stays with a world that is saved. It comes across to the world that a newer system makes when it is NIL or a name, whose function the text defines there; a function itself is no text. A world that is made anew for another reason has the system's clock again, unless /home/init.lisp gives it another.

Parentheses

In a REPL window, and in Emma, the parentheses that belong together are in one colour. The outermost pair has the first of six colours, a pair inside it the second, and so on, and a pair that lies deeper than six takes them from the first again. So the parenthesis that closes another is found by its colour, and one that closes nothing stands out in red.

While the last character that you typed is a closing parenthesis, the one that opens it has a block under it, like a cursor in a paler shade: that is where the form began which you have just ended. It can be in a line further up, since a form is often more lines than one. In Emma the block is there whenever the cursor stands right behind a closing parenthesis. It goes with the next character, and there is none while the opening parenthesis is out of the window.

A parenthesis in a string, in a comment, after a backslash or between two bars is none to the reader, and neither is the character of #\(: those look like the text around them.

The colours are three variables of the package CLARA.SYNTAX, each colour its red, green and blue from 0 to 255:

> clara.syntax:*colors*
((255 121 198) (139 233 253) (241 250 140) (189 147 249) (255 184 108) (80 250 123))
> (list clara.syntax:*stray* clara.syntax:*hint*)
((255 85 85) (98 90 134))

clara.syntax:*colors* are the colours of the pairs, the outermost pair's first: after (setq clara.syntax:*colors* '((255 255 255) (160 160 160))) there are two, and with NIL there are none, and a parenthesis looks like any other character. clara.syntax:*stray* is the colour of a closing parenthesis that nothing opens, and clara.syntax:*hint* that of the block; NIL for either does without it. In a REPL window the lines that were typed before keep the colours that they had, and Emma's window is in the new ones with the next key. The three stay with a world that is saved, and /home/init.lisp is where to say them for every world that is made anew.

The screen of the first prompt, before there are windows, shows none of this, and neither does a terminal on the serial port.

A program of your own that shows Lisp can ask what the windows ask. clara.syntax:scan goes through a text and calls a function for every parenthesis that counts, with its place in the text, its level, which is how many pairs it lies within, and for a closing one where the one is that opens it:

> (let ((seen nil))
    (clara.syntax:scan "(car '(1 \")\"))" nil 'here
                       (lambda (index level opening)
                         (push (list index level opening) seen)))
    (reverse seen))
((0 0 NIL) (6 1 NIL) (12 1 (HERE . 6)) (13 0 (HERE . 0)))

A closing parenthesis that nothing opens has NIL for its level. The second argument is what is known of the text before this one, NIL at its start, and what clara.syntax:scan gives back is what is known after its last character: a text can be gone through a piece at a time. The third names the piece, and an opening parenthesis is remembered as that name and its place in the piece. When the pieces are the lines of a text, which have no ends in them, clara.syntax:next-line makes of what is known at the end of a line what is known at the start of the next. clara.syntax:color gives the pixel for a level, as clara.draw:draw-text takes one, and clara.syntax:hint the pixel of the block; each is NIL when there is to be none.

Highlighting, cutting, copying and pasting

Text in a window is highlighted with the pointer: press its left button where the text begins, move the pointer with the button held, and let go where the text ends. What is highlighted stands on a blue ground, from the one place to the other as the text is read, over as many lines as lie between. A character counts once the pointer has passed its middle. A click without a move highlights nothing, and takes away what was highlighted before. Three keys go with it:

Ctrl-Ccopies what is highlighted.
Ctrl-Xcuts it: it is copied, and taken out of the text.
Ctrl-Vputs in what was cut or copied last, in this window or in any other.

There is one such text for all the windows, so what is copied in a REPL window can be put into Emma, and what is cut in Emma can be typed at a prompt. Each window does with the keys what fits it:

A REPL windowlets any of its rows be highlighted, what was typed there and what was printed. Page Up and Page Down work while the button is held, so the text can be more than the window holds. Ctrl-C copies it and takes the highlight away. With nothing highlighted the key is what it always was, and stops what the window is evaluating. Ctrl-X copies too, since what a window has printed cannot be taken out of it. Ctrl-V types what was copied, as if on the keyboard: every line of it that has an end is read as it stands, and its last line waits at the prompt for Enter. A line that was too long for one row is copied as the one line that it is.
Emmahas all three, and what is typed takes the place of what is highlighted; Backspace and Delete take it out. The cursor is at the end of it where the pointer is, and a pointer that is moved above the window or below it takes the text along. A key that moves the cursor takes the highlight away.
Jaidcopies the name that is picked, with its directory, at Ctrl-C: /clara/notes.txt, for a form at a prompt or for Emma's Ctrl-O.
Arestakes what was copied into the row of the address, at Ctrl-V, while an address is typed there. What a page says cannot be highlighted yet.

Where one line is asked for, the name of a file in Emma or an address in Ares, Ctrl-V puts in the first line of what was copied. A program reads and writes the same text with clara.windows:clipboard:

> (clara.windows:clipboard)
""
> (setf (clara.windows:clipboard) "(+ 1 2)")
"(+ 1 2)"
> (clara.windows:clipboard)
"(+ 1 2)"
> clara.windows:*highlight*
(48 64 112)

After that, Ctrl-V in a REPL window types (+ 1 2) at its prompt. The text is a string, with a new line where a line ends, and it is empty until something is copied. It stays with a world that is saved. clara.windows:*highlight* is the colour of the ground, its red, green and blue from 0 to 255, which what is highlighted next stands on; (clara.windows:highlight) gives the pixel of it, as clara.draw:draw-text takes one, for a window of your own that highlights. The screen of the first prompt, before there are windows, has no pointer, and nothing is highlighted there.

A window of your own

The functions are in the package CLARA.WINDOWS. A window's inside is a surface, and is drawn on like any other. What was drawn reaches the screen with clara.windows:show, as far as the window can be seen behind the others.

> (defvar *window* (clara.windows:open-window "A window of my own" 240 120))
*WINDOW*
> (defvar *inside* (clara.windows:window-surface *window*))
*INSIDE*
> (clara.draw:fill-rectangle *inside* 20 20 80 60 *red*)
T
> (clara.draw:draw-text *inside* 112 44 "Hello" *ink*)
T
> (clara.windows:show *window*)
T
> (clara.windows:move-window *window* 400 300)
400
300
> (clara.windows:launch "REPL")
#<THREAD "REPL">
> (mapcar #'clara.windows:window-title (clara.windows:windows))
("REPL" "A window of my own" "REPL")
> (clara.windows:window-title (clara.windows:raise-window *window*))
"A window of my own"
  • clara.windows:open-window takes a title and the width and height of the inside, in pixels, and gives the window, on top of the others and the colour of the console's paper. With :x and :y it goes where they say, and otherwise a step down and across from the one before. A window is 24 pixels wide or more.
  • clara.windows:window-surface is what to draw on, and clara.windows:show puts on the screen what was drawn since the last time. It gives NIL when there was nothing.
  • clara.windows:move-window moves a window so that the corner of its inside is at a place on the screen, and gives the place it came to, which is clara.windows:window-position from then on: a window stays below the bar, and never leaves the screen altogether.
  • clara.windows:windows lists the windows from the top one down, clara.windows:focused-window is the first of them, and clara.windows:raise-window brings one to the top.
  • clara.windows:close-window takes a window off the screen and gives its memory back.

A window belongs to the thread that opened it. That thread draws on it, shows it and closes it, and close-window from any other thread is an error for as long as the first one lives. Five functions can be given when a window is opened, for what happens to it meanwhile:

> (defvar *typed* nil)
*TYPED*
> (defvar *keys* (clara.windows:open-window "Keys" 160 40 :key (lambda (code) (push (code-char code) *typed*))))
*KEYS*
> (clara.windows:key-typed 97)
97
> *typed*
(#\a)
> (list (clara.windows:close-window *keys*) (clara.windows:close-window *window*))
(NIL NIL)
  • :key is called with the code of every character that is typed while the window has the focus. clara.windows:key-typed is what the keyboard's driver calls; here it stands in for a key.
  • :pointer is called when a button of the pointer goes down or comes up on the inside of the window, with the place, counted from the corner of the inside, and the buttons that are down: 1 for the left one, 2 for the right, 4 for the middle. clara.windows:pointer-moved is what the drivers of mice and tablets call, with a place on the screen and the buttons.
  • :drag is called when the pointer moves while the left button is still down that went down on the inside of the window, once it is three pixels away from where that was, and from then on with every move until the button comes up: with the place, counted from the corner of the inside like :pointer's, and the buttons. The place can lie outside the window, to its left or above it too, where it is counted below nought. That is what highlighting is made of.
  • :drop is called when the left button comes up on the inside of the window while the pointer carries something: with the place, and with what is carried, which is a text. What the pointer carries is below.
  • :close is called when the x in the title is clicked, and a window that was given none has no x. It is for the function to see that the window is closed, by the thread that opened it.

The five are called in the thread of the keyboard or of the mouse, not in the window's own. They should note what they were told, or signal an event, and leave the drawing to the thread that the window belongs to.

A program lets something of its window's be taken to another window by having the pointer carry it, as a text: Jaid does so with the name of a file. (clara.windows:carry window text) says what is carried, and holds while the left button is down that went down on the inside of that window. When the button comes up, the window that it comes up on is told through its :drop, whichever program's it is, and the window that the text was carried from is told where it was let go, through its :drag, with no button down. Then nothing is carried any more.

> (defvar *let-go* nil)
*LET-GO*
> (defvar *from* (clara.windows:open-window "From" 160 40 :x 40 :y 100))
*FROM*
> (defvar *to* (clara.windows:open-window "To" 160 40 :x 300 :y 100
                                          :drop (lambda (x y text) (setq *let-go* (list x y text)))))
*TO*
> (clara.windows:carry *from* "/hello.lisp")
NIL
> (clara.windows:pointer-moved 50 110 1)
NIL
> (clara.windows:carry *from* "/hello.lisp")
T
> (clara.windows:pointer-moved 310 120 0)
NIL
> *let-go*
(10 20 "/hello.lisp")
> (list (clara.windows:close-window *from*) (clara.windows:close-window *to*))
(NIL NIL)

carry gives T when the pointer carries the text from then on, and NIL when it does not: no button is down, as for the first of the two above, or it went down on another window. clara.windows:pointer-moved stands in for the mouse here, with a place on the screen and the buttons, the way key-typed stood in for a key.

A sixth function, :unfinished, is for a program that holds something which would be lost if its window went: a function that gives a few words about it, such as "text that is not saved", or NIL when there is nothing. The machine asks every window before it shuts down, and does not while one answers in words. (clara.windows:unfinished) gives the windows that do at the moment, each with its words.

A window that is opened with :events t does that by itself: it keeps what happens to it, and its program asks for the next thing when it is ready for it, in its own thread, where it can draw.

> (defvar *heard* (clara.windows:open-window "Heard" 160 40 :events t))
*HEARD*
> (clara.windows:key-typed 97)
97
> (= (clara.windows:key-typed clara.input:+up+) (+ char-code-limit 1))
T
> (clara.windows:next-event *heard*)
(:KEY 97)
> (equal (clara.windows:next-event *heard*) (list :key clara.input:+up+))
T
> (clara.windows:next-event *heard* 100)
NIL
> (clara.windows:rename-window *heard* "Heard it")
"Heard it"
> (clara.windows:close-window *heard*)
NIL
  • clara.windows:next-event gives what happened next, and waits when nothing has: for as long as it takes, or for so many milliseconds, after which it gives NIL. (:key 97) is a key, (:pointer 12 30 1) a button that went down or came up, with the place on the inside and the buttons, and (:close) a click on the x, which such a window always has. A window that is opened with :events t :drag t keeps (:drag 40 30 1) as well, for the pointer that was moved with the left button held; of several such moves that nobody has taken yet, it keeps the last. One that is opened with :drop t keeps (:drop 40 30 "/hello.lisp") for a text that the pointer let go on it. The program of such a window says what the pointer carries once it has taken the button that went down, and not before: carry gives NIL while a button is still among what the window keeps.
  • A key is the code of the character it types. The keys that type none have codes too, past the last that a character can have, which is char-code-limit: clara.input:+up+, +down+, +left+, +right+, +home+, +end+, +page-up+, +page-down+, +insert+, and +f1+ for the first of the twelve function keys, with the others after it. Escape is 27, Delete 127, and a key that is typed with Alt held has clara.input:+alt+ added to its code.
  • clara.windows:rename-window gives a window another title.

Text in a window

A terminal is a window with a stream: what is written to the stream is drawn in the window, in rows that move up when the last one is full, and what is typed in the window comes back from the stream a line at a time. The package is CLARA.TERMINAL.

> (defvar *notes* (clara.terminal:open-terminal "Notes" :columns 40 :rows 8))
*NOTES*
> (format (clara.terminal:terminal-stream *notes*) "written from the serial port~%")
NIL
> clara.terminal:*rows-kept*
100000
> (clara.terminal:clear *notes*)
NIL
> (clara.windows:close-window (clara.terminal:terminal-window *notes*))
NIL

clara.terminal:open-terminal takes a title and gives a terminal of 80 columns and 24 rows unless :columns and :rows say otherwise; :x, :y and :close are the window's, and :font says what its letters are. clara.terminal:terminal-stream is its stream, for format, write-line and read-line, and clara.terminal:terminal-window its window. clara.terminal:clear makes every row blank, and forgets the rows that had left the window. A line that is read from the stream is typed the way a line is typed at a REPL's prompt, with its parentheses in their colours, and what the window shows is highlighted and copied as in a REPL window.

Those rows are kept, in a terminal of your own as in a REPL window, and Page Up and Page Down show them again; the two keys are the window's, and never come back from the stream. clara.terminal:*rows-kept* says how many rows a terminal keeps beyond the ones in its window: the newest 100000, until the variable is set to another number, or to NIL for all of them. All of them is as much as the memory holds, since the rows are in the heap like everything else: a program that writes without end fills it then, and every prompt answers the heap is full until the window with all those rows is closed. With a number the oldest rows go as new ones come, and the program can go on for as long as it likes. The rows of a window are part of a world that is saved while the window is open: a window that has had its 100000 rows makes that world some 27 MiB larger, and it stays so. Every terminal goes by what the variable says when a row is finished, so (setq clara.terminal:*rows-kept* nil) at a prompt is for the window that it is typed in as well. It stays with a world that is saved, and /home/init.lisp is where to say it for every world that is made anew.

A row is so many cells, and an emoji has two of them: one that the row has a single cell left for begins the next row. What is highlighted and copied is whole emoji, and the text that was written, without the characters that show nothing by themselves, which a terminal does not keep.

The lines that the arrows bring back at a REPL's prompt are a list, which a program can read and write:

> (setf (clara.terminal:history) (list "(+ 1 2)" "(list 'a 'b)"))
("(+ 1 2)" "(list 'a 'b)")
> (clara.terminal:history)
("(+ 1 2)" "(list 'a 'b)")
> clara.terminal:*lines-kept*
1000
> (setf (clara.terminal:history) 5)
error: the lines that were typed before are a list of strings, and 5 is not one

(clara.terminal:history) gives the lines, the newest first, in a list of your own: changing that list changes nothing. (setf (clara.terminal:history) lines) makes other lines of them, a list of strings, and with NIL none is remembered any more. After the form above, the arrow up in a REPL window brings back (+ 1 2), and the arrow up again (list 'a 'b). A line comes back as if it were typed, so what no key types is not in it. clara.terminal:*lines-kept* says how many lines are remembered, the newest of them: 1000, until it is set to another number, or to NIL for all of them. It is looked at whenever a line is remembered, so a smaller number takes the oldest lines with the next line that is read. Like the rows, it stays with a world that is saved, and /home/init.lisp is where to say it for every world that is made anew.

The lines are the ones that were typed at a prompt. A line that a program of your own reads from a terminal's stream, with read-line, is not remembered, and the arrows do nothing while it is typed.

The letters of a window

A terminal is a grid of cells, and its letters are the console's unless it is told a font: any family, at any size, bold, italic, underlined or struck through. Its cells are then as large as the font's, and the window as large as its cells.

> (defvar *large* (clara.terminal:open-terminal "Large" :columns 24 :rows 4
                    :font (clara.type:font "Mono" 24 :bold t)))
*LARGE*
> (format (clara.terminal:terminal-stream *large*) "bold, at 24 pixels~%")
NIL
> (clara.windows:close-window (clara.terminal:terminal-window *large*))
NIL
> (setq clara.windows:*text-font* (list "Mono" 16))
("Mono" 16)
> (clara.type:font-size (clara.windows:text-font))
16
> (setq clara.windows:*text-font* nil)
NIL

:font is one of clara.type:font's, or NIL for the console's letters. A terminal that is told nothing is written in what clara.windows:*text-font* says, and so are the windows of the applications that are grids of text: the REPL, Emma, Jaid and Parker. The variable is said like clara.windows:*font*: a list of a name, a size and whatever else clara.type:font takes, or a font, or NIL, which is what it is as the system comes, the console's letters. (clara.windows:text-font) gives the font that it says, or NIL. After (setq clara.windows:*text-font* (list "Mono" 16)) the next REPL window, and the next window of each of the others, is in Mono at 16 pixels, with as many columns and rows as before where the screen has room for them.

A window reads the variable as it opens and keeps its font for as long as it is open: the windows that are there stay as they are. One window can be told its own font as it is launched, whatever the variable says:

> (clara.windows:launch "REPL" :font (clara.type:font "Mono" 20))
#<THREAD "REPL">
> (clara.windows:launch "Emma" "/hello.lisp" :font (clara.type:font "Mono" 14 :italic t))
#<THREAD "Emma">
> (clara.windows:launch "Jaid" "/" :font nil)
#<THREAD "Jaid">

Mono is the family that is made for it. A font whose letters differ in width can be had as well, and has every letter in a cell as wide as its widest, so its words come out spaced. A font that cannot be had, a file that is not there, is said on the serial port, and the window opens in the console's letters. The variable stays with a world that is saved and comes across to the world that a newer system makes, and /home/init.lisp is where to say it for any other world that is made anew. The first prompt, before the window manager, keeps the console's letters, and so does what the system says when something goes wrong.

An application

An application is a name and a function. clara.windows:launch calls the function in a thread of its own and comes back with that thread once the application has its window. When the function is done, or its thread is stopped, the windows that the thread opened are closed for it.

> (clara.windows:define-application "Hello"
    (lambda ()
      (let ((terminal (clara.terminal:open-terminal "Hello" :columns 30 :rows 4)))
        (format (clara.terminal:terminal-stream terminal) "hello from an application~%")
        (sleep 2))))
"Hello"
> (clara.windows:applications)
("REPL" "Emma" "Jaid" "Ares" "Settings" "Parker" "Hello")
> (clara:join-thread (clara.windows:launch "Hello"))
NIL

The window is there for two seconds, and goes with its application. From now on Hello is in the list under Applications, below the six that come with the system, until it is moved. REPL is clara.terminal:repl, the first application and the one that is launched when the window manager starts; Emma, Jaid, Ares and Settings are the subject of the next chapter, and Parker of the one after it.

What the list has under its line are commands: a name and a function of no arguments, which is called in a thread of its own when the name is picked, and which opens no window that anything waits for.

> (clara.windows:commands)

"Collect"
> (clara.windows:remove-command "Collect")
"Collect"

The order of the list

A name stands in the list where it was first defined, under the ones that were there. clara.windows:move-up and clara.windows:move-down take a line one place up or down, by its name, and answer with the names of its kind as they stand then.

> (clara.windows:move-up "Hello")
("REPL" "Emma" "Jaid" "Ares" "Settings" "Hello" "Parker")
> (clara.windows:move-down "restart")
("Shut Down" "Restart")
> (clara.windows:move-down "Restart")
("Shut Down" "Restart")
  • An application moves among the applications and a command among the commands, on its side of the line. The first of its kind stays where it is when it is moved up, and the last when it is moved down, as Restart did the second time. A line goes further by being moved again.
  • The name is taken in letters of either case. When an application and a command have the same name, it is the application that moves. A name that the list does not have is an error, which says the names that it has.
  • A list that is open stays open, and shows the move.
  • Moving a line changes the list and nothing else. The application that is launched when the window manager starts is the one that was defined first, REPL, wherever it stands by then.
  • The order is part of the world. A world that is saved has it, and an upgrade carries it to the newer system. It is no definition, so it is not written down as text: a world that is made of the text alone has every name where it was first defined.

Starting in it

A world that is saved while the window manager runs starts in it: the screen goes from the boot report straight to the windows.

> (clara:save-image)
"/clara/clara.image"

The report of the next start says so, in its last line before the prompt of the serial port:

windows: the window manager has the screen again, as it had when the world was saved
> (list (clara.windows:running-p) (mapcar #'clara.windows:window-title (clara.windows:windows)))
(T ("REPL"))
> (list (clara.windows:applications) (clara.windows:commands))
(("REPL" "Emma" "Jaid" "Ares" "Settings" "Hello" "Parker") ("Shut Down" "Restart"))

T

What is defined comes back, the applications among it, in the order that the list was left in. The windows that were open do not: a window is pixels and a thread, and an image has neither, so the window manager starts with one REPL, as it does the first time. clara.windows:stop ends the applications and gives the screen back to the console, cleared; a world that is saved after that starts at the console again.

A window is the size it was opened with. Alt and Tab is the one key that is the window manager's own: nothing on the keyboard opens the list of applications, moves a window or closes one, which the pointer does, and the pointer has one shape.

Emma, the editor

Emma in the list opens a window with no text in it yet, whose title is Emma. From a prompt, Emma is launched with the name of a file, and the window's title is Emma - and that name:

> (find-package "CLARA.EMMA")
NIL
> (clara.windows:launch "Emma" "/hello.lisp")
#<THREAD "Emma">
> (list (package-name (find-package "CLARA.EMMA"))
        (clara.windows:window-title (clara.windows:focused-window)))
("CLARA.EMMA" "Emma - /hello.lisp")

After the name, :columns and :rows say how large the text's part of the window is, in characters, and :x and :y where the window goes: (clara.windows:launch "Emma" "/hello.lisp" :columns 60 :rows 20). Without them it is 80 by 24, or what the screen has room for. :font says what the text is written in.

The window shows the text, with a bar under the place where what is typed goes in, and below the text a row that says which file this is, whether the text has changed since it was read or saved, and the line and the column of the cursor. That row is also where Emma says what it did, and where it asks for the name of a file and for what to find. The parentheses of the text that belong together are in one colour, and while the cursor stands right behind a closing one, the one that opens it has a block under it.

A charactergoes in at the cursor.
Enterbegins a new line, as far in as the line it comes from.
Backspace, Deletetake out the character before the cursor, and the one at it. At the start and at the end of a line they join two lines.
Tabspaces, up to the next column that is a multiple of eight.
The arrowsmove the cursor by a character and by a line.
Home, Endthe start and the end of the line.
Page Up, Page Downa window's worth of lines up or down.
A clickputs the cursor where the pointer is.
The pointer, moved with its left button heldhighlights the text from where the button went down to where the pointer is. What is typed then takes its place, and Backspace and Delete take it out.
Ctrl-X, Ctrl-Ccut and copy what is highlighted.
Ctrl-Vputs in what was cut or copied last, in this window or in any other, at the cursor and in the place of what is highlighted.
Ctrl-Ssaves the text in its file. A text that has no file yet is asked for a name, which the window's title has from then on.
Ctrl-Oasks for the name of another file, and the text becomes that of the file.
Ctrl-Fasks what to find, and looks for it from the cursor on. What is found is highlighted, with the cursor behind it.
Ctrl-Gfinds the same once more, further down, or from the start of the text when there is none further down.
Ctrl-Kcuts from the cursor to the end of the line, and at the end of a line the end itself. Typed several times in a row, it cuts as many lines. What it cuts is what was cut last, like what Ctrl-X cuts.
Ctrl-Yputs that back at the cursor, as often as it is typed: it is Ctrl-V under the name that it had before.
Ctrl-Eevaluates the text, form by form, as load would: what it defines is defined, in every window. The row says how many forms there were, or what went wrong and in which line, where the cursor goes. Ctrl-C stops forms that do not end.
Ctrl-Q, the x in the titleclose the window.

While the row asks for a name, what is typed is the name: Enter hands it over, Backspace takes a character of it back, Ctrl-V adds the first line of what was copied last, and Escape gives the question up. A name is a whole one, from the top of the volume, like /clara/notes.txt. A file that is not there yet is a new one, which the first Ctrl-S makes. The row asks what to find in the same way.

Ctrl-F asks Find: in that row, and Enter looks for what was typed there: from the cursor to the end of the text, and when it is not there, from the start of the text down to the cursor. A letter is found in either case, so defun finds DEFUN and Defun too. Every other character is itself, a space as well, and what is looked for lies in one line. What is found is highlighted, with the cursor behind it, and a line that the window did not show comes to the middle of it. From there:

Ctrl-Gfinds the next one, and goes on doing so after other keys: Emma remembers what was looked for last in that window. Before anything was looked for, it asks as Ctrl-F does.
A character, Ctrl-Vtakes the place of what was found, as of anything that is highlighted. That is how one thing is put where another was: find it, type the other, and Ctrl-G for the next.
Ctrl-Ccopies what was found, in the letters that the text has it in.
An arrow, a clickleaves it as it is, and nothing highlighted.

The row says what came of it when that is not plain to see:

Ctrl-G finds the next oneIt was found, further down, and there are more.
none further down: the first in the textThere was none between the cursor and the end of the text, so this is the first one, from the start.
the only one in the textIt was found, and there is no other: Ctrl-G would find the same again.
not in the text: and what was looked forThere is none. The cursor stays, and so does what was highlighted.

A text that has changed is not thrown away at the first asking. Ctrl-O, Ctrl-Q and the x say that the text is not saved, and do what they were asked when the same key comes again right after.

What to know about Emma as it is now:

  • A file is its lines. It is saved with a new line after each, so a file that did not end in one has one afterwards. The line with nothing in it after the last is where the text ends.
  • A character that the screen's font does not have shows as a box, a tab and an emoji among them, and is kept as it is.
  • There is no undo. Text is highlighted with the pointer and not with the keyboard.
  • What is looked for is found forwards, at Enter, and as it was typed but for the case of its letters, which are the letters from a to z: nothing looks backwards, shows what there is while it is typed, tells a capital from a small letter or goes by a pattern, and one thing is put in the place of another by typing it there.
  • What the forms of Ctrl-E print goes to the console, which is the serial port while the windows are on the screen. They are read in the package COMMON-LISP-USER unless the text says in-package.
  • Each Emma window is a thread of its own with its own text. Two that have the same file open know nothing of each other.

Letters are bold, slanted, underlined, struck through, smaller, raised or as they are typed where the page makes them so. What to know about Ares as it is now:

  • Every page is asked for by HTTPS, and by nothing else. An address that is written with http://, typed or in a link, is asked for with https:// in its place, and a web server that does not answer that way shows no page here. What that section says of certificates, of the time and of servers that only have an older TLS holds for every page.
  • Nothing that a page says about its looks is read, in a style sheet or anywhere else: no colours, no letters of the page's choosing, no columns, nothing that is put beside something else or hidden by a rule. A page that hides parts of itself that way shows them here.
  • No picture is fetched. Where a page has words for a picture, those stand for it, between brackets, [A sun over its horizon], and [picture] where it has none.
  • No script is run. A page that is put together by its scripts shows what it has without them, which can be nothing.
  • A form shows what its fields and buttons are, [________] and [Search], and nothing can be typed into one or sent: nothing is searched for and nothing is signed in to.
  • A page that does not say how it is written is read as UTF-8, and any other way of writing as that of western Europe, a byte to the character. An emoji is its picture, and any other character that the system's two fonts have no shape for shows as a box: they have the letters of Latin, Greek and Cyrillic writing.
  • A page is fetched whole before any of it shows, and the window does nothing else meanwhile: what is typed waits. A page of more than four megabytes is not taken. What is neither a page nor a text is said to be what it is, and not kept anywhere.
  • Where a page has another page in it, a link to that one stands in its place.
  • What a page says cannot be highlighted, and nothing of it is copied.
  • Nothing outlasts a window: no list of where it was, no addresses that are kept, nothing that a web server asked it to remember. The window is the size that it opened with.
  • Every web server that is asked is told who asks, as by anything that this system fetches: ClaraOS and its version.
  • Each Ares window is a thread of its own. Its function is clara.ares:browse, which takes what launch takes after the name and comes back when the window closes.

  • Emma, Jaid, Ares and Settings are unloaded and launched again the same way, and the system's emma.lisp can be changed in Emma: (clara.system:system-file "emma.lisp") is its name. A file that is installed by a name without a directory, as those four are, is one of the system's own.

What installing does

A package that is installed is a directory on the disk that the machine was started from, /packages/sun/, with the package's files and a file package, which says what the package is. Nothing else is written, and an upgrade of the system leaves that directory alone.

  • The files that the package says are to be loaded are loaded at once, so what they define is there: sun has one, which defines sun:disc. Its applications are in the list under Applications at once as well, and the file of each is loaded when the application is first picked, like any application in a file.
  • Every file of a package is fetched before the first one is written, so a package that cannot be had whole leaves nothing on the disk. One whose file fails as it is loaded is not installed either, and the reason is said.
  • The disk says what is installed, and the world follows it. A world that is saved has its packages in it. A world that is made of the files, at a first start or after an upgrade, loads every package that the disk has, each after the ones that it needs, and before the text that you keep, so /home/init.lisp can use what a package defines. The start says packages: sun 1.0.0 is installed, and is loaded into this world, and (clara.system:report) says it again.
  • A world that was saved before a package was installed, on a machine that then stopped without saving, takes the package at its next start; one that was saved before a package was taken out lets go of it. Either is said.
  • A package that fails as a start loads it is said to have, with the reason, and the start goes on: packages: sun 1.0.0 is installed, and did not load:, and under it the reason. It stays installed, and the next start tries it again. A package gets as long as a file of /home does, clara.system:*patience*.
  • After two starts that did not come to a prompt a package may be the reason, so the world is made without any: (clara.parker:load-installed) loads them, when what was wrong has been taken out.
  • Taking a package out stops its applications, takes them out of the list, deletes the packages of the language that its files made, with all that they defined, and then its directory. What a file of it defined somewhere else, in COMMON-LISP-USER for one, stays in the world.
  • A newer version takes the older one's place the same way: the older one is taken out of the world and off the disk, and the newer one is written and loaded.
> (clara.parker:load-installed)
NIL

Where packages come from

Packages are published at a source: a directory on a web server, with an index that says what is there, and beside the index a signature of it. The system knows of one, https://claraos.org/packages/, which is beside its own releases and signed with the same key.

> clara.parker:*sources*
(("https://claraos.org/packages/" "2c67792528bac0b3570bb966e176e9b60ee04bfa0084ce50676db6cd8fca8dc6"))
  • A source is the address of the directory and the public half of the key that its index is signed with, 64 digits. The address begins with https://: packages are fetched by HTTPS and in no other way.
  • Nothing is believed for having arrived. The index is held against its signature, and every file against the index, by its length and its SHA-512. What fails either is not installed, and the disk is as it was.
  • The machine asks a source when it is told to, by Parker's window as it opens and at Ctrl-R, and by available, install and update. It asks at no other time.
  • Another source is one more pair in the list, and /home/init.lisp is the place to say so, since a world that is made again starts with the list above: (setq clara.parker:*sources* (append clara.parker:*sources* '(("https://example.org/packages/" "8c33...")))). Of two sources that have a package of one name, the first is the one that it is taken from.
  • A package is code, and code does on this machine whatever it likes: ClaraOS keeps no program away from another, or from the system. Naming a source is trusting whoever has its key with the machine, as an upgrade trusts whoever has the key of the releases.

A package of your own

A package is written as a directory of its name, with its files and a file package that says what it is. This is the one of sun, which is in ClaraOS's repository, in packages/sun/, with its two files of Lisp:

What is in packages/ of the repository is what https://claraos.org/packages/ has: each time a change there is merged, the packages are laid out and their index is signed, with the system's release. A newer version of a package is its directory with a higher version in the first line of package.

python3 tools/release.py key my.key                          # once: the secret half goes into my.key, the public half is printed
python3 tools/release.py packages packages published my.key  # the packages of packages/, laid out in published/

  • clara.sound:beep is a short, high tone, for a program that has something to say and no words for it.
  • clara.sound:tone takes a pitch and how long the tone lasts, in thousandths of a second, from 1 to 60000. A pitch is how many times a second the wave goes round, from 20 to 20000: 440 is the A that an orchestra tunes to, and twice the number is the same note an octave higher. The name of a note is a pitch too.
  • :wave is the shape of the wave, which is what gives a tone its colour. :sine is the plainest, and what a tone is unless you say otherwise; :square is hollow and loud, the sound of the first computer games; :triangle is soft; :sawtooth is sharp, like a bowed string; and :noise is a hiss, which is finer the higher its pitch.
  • :volume is how loud, from 0 to 100, and :pan where between the two sides: -100 is the left side alone, 100 the right side alone, and 0, which it is unless you say otherwise, both alike.
  • clara.sound:wait returns when everything has been played. clara.sound:stop ends what is being played: a note that is sounding is let go of, and is gone a few hundredths of a second later.

> (clara.sound:wait)

> (clara.sound:tone 'h4 100)
error: H4 is not a note: a note has a name like C4, F#3 or BB5, or is a number of times a second, or REST
  • A note is named by its letter, from a to g, and its octave, from 0 to 8. c4 is the C in the middle of a piano, a4 the A of 440, and an octave begins at its C. A # after the letter is the black key above it, as in f#3, and a b the one below, as in bb5; an s does what the # does. Without a number it is the octave 4. The name can be a symbol, a keyword or a string, and a number in the place of a note is a pitch, as for a tone.
  • clara.sound:play takes a list of notes and plays them one after the other, each for a step. :tempo is how many steps there are to the minute, from 1 to 6000, and 120 unless you say otherwise.
  • A list in the place of a note is the notes that sound together, up to eight of them, and a number at its end is how many steps they last: (g4 2) is a G for two steps, (c4 e4 g4) three notes at once, and (c4 e4 g4 2) the three for two steps.
  • rest, or nil, is a step in which nothing sounds.
  • :wave, :volume and :pan are what they are for a tone, for every note of the list.

A note comes up and goes down again over a few thousandths of a second, so that it does not begin or end with a click, and is as loud in between as it was asked to be. There is no instrument here whose notes die away, as a piano's do, and no note slides into the next.

Several at once

What is played while something else is still sounding is added to it, up to sixteen things at a time; one more than that is not played, and the function that asked gives NIL. Two calls one after the other begin as far apart as the second took to be worked out, and in music that is heard. clara.sound:together has everything that the forms inside it play begin at the same instant:

> (clara.sound:together
    (clara.sound:play '(e4 d4 c4 d4 e4 e4 (e4 2)) :tempo 480 :wave :square :volume 40)
    (clara.sound:play '((c3 4) (g3 4)) :tempo 480 :wave :triangle))
T
> (clara.sound:wait)
T

How loud

clara.sound:*volume* is how loud the machine is, from 0 to 100. It holds for everything, also for what is already sounding, and it is set, with SETQ: a LET around one call changes nothing, since the sound is put together by another thread than the one that asked for it.

> (setq clara.sound:*volume* 50)
50
> (clara.sound:beep)
T
> (setq clara.sound:*volume* 100)
100

At 100 and with the machine at 100, a wave goes a quarter as far as the card's numbers do, so that four things can sound together as loud as that and still be whole. What comes to more than the numbers hold is cut off at their ends, which is heard as a rasp.

Files of sound

clara.sound:play-file plays a file of sound of the commonest kind, a WAVE file, whose name usually ends in .wav: plain numbers of 8 or 16 bits, on one side or two, at any pace from 1000 to 192000 frames a second. The file is read whole before the first of it is heard. :volume and :pan are what they are for a tone, and at 100 a file is as loud as it was made.

> (clara.sound:play-file "/home/chime.wav" :volume 60)
T
> (clara.sound:play-file "/home/song.mp3")
error: /home/song.mp3 is not a file of sound of the kind that is read here, a WAVE file

A file gets onto the machine like any other: A disk of your own. On a Mac, afconvert -f WAVE -d LEI16 song.mp3 song.wav makes such a file of a file of another kind.

A machine without a sound card

On a machine that has no sound card, or none that there is a driver for, nothing is played, and that is no error: every function here gives NIL there and does nothing else, so a program that makes a sound when a key is pressed is the same program on such a machine. What is wrong with what was asked for, a note that is none, is an error on every machine. (clara.sound:card) says what plays, or NIL:

> (clara.sound:card)
"the sound card 00:07.0: 48000 frames a second, left and right"

There are drivers for two cards: virtio's, which make run-aarch64 gives a machine, and Intel's (High Definition Audio), which is what UTM gives one. Of a card of the second kind the line says of Intel's kind behind its place, and a machine with both plays on the one that comes first on its bus. What you play is heard a few hundredths of a second later, which is the time the numbers take through the card and through your computer. Nothing is recorded.

The two differ in one thing that can be heard. A virtio card plays what it is handed and waits for more. Intel's plays by the clock, so a machine that is busy for longer than a few hundredths of a second leaves a gap in what it plays there, and goes on behind the gap with what came next: nothing is lost, and nothing is played twice.

The package CLARA.UNSAFE

For drivers. What can be read with one of the first seven can be written with setf. The eight after give-screen are the compiler's and the translator's. The first two are a function made of code, and the code of a function: code is looked at before it is made a function, and refused when it points where it should not; that it uses its stack as it says is taken on trust, which is why the two are here. The other six are for the processor's own instructions: where the kernel keeps what they read, the instructions of a function handed to the kernel, how many bytes of them a function has, whether the processor runs a function, what the compiler made of every function that the processor does not run yet, and every function that has such instructions entered by them from then on. Those instructions are run as they are given, and nothing looks at them first. power-off and reset turn the machine off and start it again there and then, with nothing saved and nobody asked, which is what shutting down sees to before it calls them; power-button says whether the machine's power button has been pressed since it was last asked. sha-512 is the sum of some bytes of memory, by which a system's files are known to be what its list says, and start-state is what the kernel knows of this start and of the ones before it. The seven from digest to ecdsa are the arithmetic of HTTPS, on bytes of memory: a sum of them, SHA-256, SHA-384 or SHA-512; such a sum with a key; bytes closed with a key and opened again, with a tag that says nobody changed them; what two sides agree on who tell each other half of it; a number to a power, modulo another, which is what checking a signature of RSA's is; and whether two numbers are the signature that a key on a curve gives a sum.
