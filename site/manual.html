{{spleen:User manual}}

How to build ClaraOS, start it, and work at its prompt.

This manual is for version {{version}}. ClaraOS starts in a virtual machine, tests itself as it comes up, and ends at a prompt where what you type is Common Lisp: it is read, evaluated, and what it gives is printed. There is no shell and there are no commands apart from that. Listing a directory, writing a file and saving the whole system are Lisp forms like any other.

What the manual shows of the prompt was typed at a running kernel: the tests that every change has to pass type each of these sessions again and compare the answers. The front page says what ClaraOS is for and how far it has come.

{{spleen:Getting it}}

ClaraOS is built from its source, on macOS or on Linux. There is nothing to download but the repository, and nothing is installed on your computer: the result is a directory of files, and a disk image made of them, for a virtual machine to start from.

On macOS the tools come from Homebrew:

brew install llvm lld qemu sbcl

On Ubuntu they come from the distribution:

sudo apt install clang lld make qemu-system-x86 qemu-system-arm ovmf \
    qemu-efi-aarch64 netcat-openbsd sbcl python3 dosfstools

Then, on either:

git clone https://github.com/the-clara-os/clara-os
cd clara-os
make               # both kernels, and the Lisp files beside them
make test          # if you like: start every machine and check its answers

make takes a few seconds and leaves everything in build/. Building and running need clang, QEMU and Python 3, which macOS has with Apple's developer tools. SBCL and the rest of the list are for make test.

{{spleen:Starting it}}

Under QEMU

make run-aarch64   # virtualized on Apple silicon: it starts at once
make run-x86_64    # emulated: the firmware takes a few seconds first

A window opens, which is the machine's screen, and the terminal you started it from becomes its serial port. Both show the same report as the machine comes up, and both end at the prompt. You can type in either: in the window on the machine's keyboard, in the terminal on its serial port.

Ctrl-A Xin the terminal: leave QEMU, whatever the machine is doing
Ctrl-A Cin the terminal: QEMU's own monitor, and back
MEM=1G make run-aarch64a machine with that much memory, where it has 512 MiB otherwise

The machine starts from a disk image, build/disk-aarch64.img or build/disk-x86_64.img, which is made of the files in build/esp the first time and kept from one run to the next. Files that you write are on it the next time, and so is a world that you saved. After the next make that changed something, the disk is made again and both are gone.

In UTM

  1. make image, on macOS. It makes build/claraos.img, a disk with both kernels on it.
  2. In UTM: New, then Virtualize on Apple silicon (the machine is AArch64) or Emulate (x86_64), operating system Other. Skip the ISO. Leave "UEFI Boot" checked. 512 MiB of memory is plenty.
  3. Remove the drive that UTM made. Then Drives, Import, build/claraos.img, with the interface VirtIO: that is the disk ClaraOS has a driver for. With any other interface the machine still starts, and has no files.
  4. Add a Serial device, mode "Built-in Terminal". The system talks there as well as on the screen, and you can type there.
  5. For typing in the screen's own window, add a keyboard that ClaraOS has a driver for. UTM gives a machine USB devices, which it does not have one for. Under QEMU, Arguments, add two: -device virtio-keyboard-pci and -device virtio-tablet-pci.
  6. Start.

UTM copies the disk into the virtual machine. To put a newer ClaraOS there, or to go back to a system that nothing was saved on, import build/claraos.img again in place of the drive.

What it needs of a machine

A processorx86_64 or AArch64. One is used, however many the machine has.
FirmwareUEFI. The kernel is the program that the firmware starts: there is no boot loader between them.
Memory128 MiB is enough to start and to work. It is given 512 MiB unless you say otherwise.
A diskA virtio disk with a FAT volume, of 12, 16 or 32 bits, behind either kind of table of partitions or without one. The volume it starts from is the one whose files it sees.
A place to typeA serial port, a virtio keyboard, or both.
A screenThe one the firmware sets up, if there is one. Without it everything is on the serial port.

It has no use yet for a network, for sound, for USB or for a clock.

What it says as it starts

The kernel reports what it finds and tests each part of itself before it uses it. On AArch64 under QEMU the report begins and ends like this:

ClaraOS: taking the machine from the firmware

ClaraOS {{version}} on aarch64: the machine is ours
exceptions: a vector table of our own at EL1, its handlers on a stack of their own
memory map: 33 regions
...
threads: self-test passed, 55 switches: by the timer, by choice, on a lock, asleep, woken, stopped
lisp: objects are tagged 64-bit words, in a heap at 0x0000400000000000 that begins with NIL
...
pci: 7 devices, by the configuration space at #x4010000000
...
input: 00:03.0 is a keyboard, QEMU Virtio Keyboard
disk: 00:02.0 has 72081 sectors of 512 bytes, 35 MiB
files: a FAT32 volume of 33 MiB on the disk 00:02.0, from its sector 2048 on
clara: reading the serial port and the keyboard: a form is evaluated, Ctrl-C stops it, Ctrl-D ends
>

The lines that begin with pci:, input:, disk: and files: say what the machine has: its devices, the keyboards and pointers among them, its disks, and the volume that names of files are looked up on. A line that begins with panic: or exception: means the kernel has stopped. When something goes wrong has more about those.

Stopping it

Ctrl-D at the prompt ends the session. The kernel says clara: nothing more to do, halting and the machine stands still. Then close the window, or stop the virtual machine. Nothing is lost by stopping at any other moment either: a file is on the disk from the moment the form that wrote it has answered.

{{spleen:The prompt}}

The prompt is > and a space. What you type after it is a form of Common Lisp. When the line holds a whole form, the form is evaluated and its value is printed, in the way it would have to be typed to mean the same thing. Then the prompt comes back.

> (+ 1 2)
3
> (list 1 "two" 'three #\4)
(1 "two" THREE #\4)
> (floor 17 5)
3
2
> (values)
> 'one "two" (+ 1 2)
ONE
"two"
3
> (list 1 2
        3)
(1 2 3)

A form that gives several values has each of them on a line of its own, and one that gives none has nothing. Several forms on a line are answered one after the other. A form that is not finished when the line ends goes on in the next line, after a prompt of two spaces, for as many lines as it takes.

Keys

Enterends the line
Backspace, Deletetakes back the last character of the line
Taba space
Ctrl-Cwhile you type: gives up the line, and the form it was part of. While a form is evaluated: stops it.
Ctrl-Dat the start of a line: ends the session, and the machine halts

That is all the editing there is. The arrow keys do nothing, and no line that was typed before can be called back. In a terminal on the serial port, the terminal's own copy and paste do what is missing: many forms can be pasted at once.

The keyboard is read as one of the United States, with Shift, Ctrl and Caps Lock, and a key that is held down repeats. What is typed on the serial port can be any character, as UTF-8. The screen shows the characters of ASCII, and a box for any other.

The screen holds 100 columns and 37 rows at 800 by 600 pixels, and what scrolls off its top is gone. The terminal on the serial port keeps whatever a terminal keeps.

Mistakes

A mistake costs a line. The system says what went wrong, in words, and the prompt comes back with everything as it was.

> (car 5)
error: CAR wants a list, and 5 is not one
> (no-such-function 1 2)
error: the function NO-SUCH-FUNCTION is not defined
> (loop)
Ctrl-C
error: interrupted from the keyboard

A form that does not end, like that (loop), runs until Ctrl-C stops it. So does one that waits for something that never comes.

{{spleen:The language}}

The Lisp is a part of Common Lisp, and not a dialect of its own: what is here means what it means in any Common Lisp, and a program that keeps to this part runs elsewhere as it stands. If you know Common Lisp, read where it stops short and go on. If you do not, any introduction to it will do, for as far as this part goes.

It is an interpreter. A function is evaluated from its text every time it is called, so it is slow by the standards of a compiled Lisp, and quick enough to drive the machine it runs on: its console, its disks and its file system are written in it.

Functions, macros and variables

> (defun fact (n) (if (< n 2) 1 (* n (fact (- n 1)))))
FACT
> (fact 20)
2432902008176640000
> (mapcar #'fact '(1 2 3 4 5))
(1 2 6 24 120)
> (defun make-counter () (let ((n 0)) (lambda () (incf n))))
MAKE-COUNTER
> (let ((c (make-counter))) (funcall c) (funcall c) (funcall c))
3
> (defmacro unless-zero (n &body body) `(if (= ,n 0) nil (progn ,@body)))
UNLESS-ZERO
> (macroexpand-1 '(unless-zero x (/ 100 x)))
(IF (= X 0) NIL (PROGN (/ 100 X)))
T
> (defvar *depth* 0)
*DEPTH*
> (defun depth () *depth*)
DEPTH
> (list (let ((*depth* 1)) (depth)) (depth))
(1 0)

A function takes its arguments in the ways Common Lisp has: required ones, &optional ones with their defaults, the rest as a list, and by keyword. A macro can take a list apart in its own list of parameters. A variable that defvar or defparameter made is special: binding it with let changes what every function sees until the let is over, as *depth* shows above.

Numbers, text and lists

> (fact 21)
error: the result is an integer too large for a fixnum, and there are no larger integers yet
> (/ 7 2)
error: 7 divided by 2 is not an integer, and there are no ratios yet
> (floor 7 2)
3
1
> (string-upcase "Hello, world!")
"HELLO, WORLD!"
> (format nil "~A and ~S make ~D" "one" "two" 3)
"one and \"two\" make 3"
> (concatenate 'string "clara" "." "image")
"clara.image"
> (list (char "Clara" 0) (char-code #\C) (code-char 955) (length "four"))
(#\C 67 #\λ 4)
> (sort (list "pci" "Boot" "console" "FAT") #'string-lessp)
("Boot" "console" "FAT" "pci")

A number is an integer of 63 bits, between -4611686018427387904 and 4611686018427387903. A result outside that is an error and not a wrong number, and so is a division that does not come out even: there are no larger integers, no fractions and no decimal numbers yet. A character is a Unicode code point, and a string holds any of them.

Structures and packages

> (defstruct point x (y 0))
POINT
> (let ((p (make-point :x 3))) (setf (point-y p) 4) p)
#S(POINT :X 3 :Y 4)
> (defpackage "PLAY" (:use "COMMON-LISP") (:export "BALL"))
#<PACKAGE "PLAY">
> (in-package "PLAY")
#<PACKAGE "PLAY">
> (list 'ball 'bat (symbol-package 'bat) 'cl-user::fact)
(BALL BAT #<PACKAGE "PLAY"> COMMON-LISP-USER::FACT)
> (in-package "COMMON-LISP-USER")
#<PACKAGE "COMMON-LISP-USER">

Names are read in the package that *package* holds, which is COMMON-LISP-USER when the system starts. What the system adds to Common Lisp is in the package CLARA, and is written with that name before it: clara:make-thread, clara:save-image.

Errors that a program handles

> (handler-case (/ 10 0) (division-by-zero () 'no-quotient))
NO-QUOTIENT
> (define-condition low-fuel (error) ((left :initarg :left :reader fuel-left)))
LOW-FUEL
> (handler-case (error 'low-fuel :left 3) (low-fuel (c) (fuel-left c)))
3
> (unwind-protect (car 5) (format t "cleaning up~%"))
cleaning up
error: CAR wants a list, and 5 is not one
> (ignore-errors (car 5))
NIL
#<TYPE-ERROR "CAR wants a list, and 5 is not one">
> (defun forever (n) (+ 1 (forever n)))
FOREVER
> (forever 1)
error: the stack is full: the forms are nested too deep, or a function calls itself without end

An error is a condition, with a type. handler-case takes the conditions whose type one of its clauses names, and unwind-protect cleans up whichever way its form is left. The system's own errors have Common Lisp's types where a program would want to tell them apart: type-error, division-by-zero, unbound-variable, undefined-function and their kin. A stack or a heap that is full, and Ctrl-C, are no errors: ignore-errors and a clause for error let them pass, and a clause for serious-condition takes them.

Where it stops short

What is refused is refused with an error that says so. Nothing is quietly taken for something else, so a program does not mean one thing here and another elsewhere.

  • Numbers are integers of 63 bits. No larger integers, no ratios, no floating point.
  • loop is the plain one, a body that is repeated until a return. Its keywords, for and collect and the rest, are not there. do, dolist and dotimes are.
  • format knows ~A, ~S, ~D, ~% and ~~.
  • The functions on sequences, mapcar, find, remove-if, sort and the others, take lists. length, subseq and concatenate take strings as well. Of their keyword arguments there is :test, with :key for member, assoc and sort, and :initial-value for reduce.
  • defstruct takes a name and slots, and none of its options.
  • Conditions are handled by handler-case. There is no handler-bind, no restart and no debugger.
  • There are no hash tables, no classes and generic functions, no typep, and no destructuring-bind.
  • A package can be made, used when it is made, and exported from. Nothing is imported or shadowed afterwards.
  • eq and eql are the same function. Letters change case as far as ASCII has them: (string-upcase "é") is "é".
  • A function can call itself some three thousand calls deep. Past that it is the error above, and not the end of the machine.
  • (declare (special ...)) and &environment are refused, and so are the reader's #., #S and #P.

Everything that is defined, at the end of this manual, is the whole list, by subject.

{{spleen:Files}}

The system reads and writes the files of the disk it started from. The name of a file is a string: the directories that lead to it and then its own name, with a slash before each, as in "/clara/boot.lisp". Letters match in either case. There is no current directory: every name starts at the top of the volume.

What is there

> (directory "/*")
("/clara/" "/EFI/")
> (directory "/clara/*.lisp")
("/clara/boot.lisp" "/clara/console.lisp" "/clara/disk.lisp" "/clara/fat.lisp" "/clara/font.lisp" "/clara/input.lisp" "/clara/listener.lisp" "/clara/pci.lisp" "/clara/self-test.lisp" "/clara/virtio.lisp")
> (probe-file "/CLARA/Boot.Lisp")
"/CLARA/boot.lisp"
> (probe-file "/clara/nothing.lisp")
NIL

directory takes a pattern, in which * stands for any characters in the last part of the name, and gives the names that fit, a directory's with a slash at its end. probe-file gives the name of a file as the disk spells it, or NIL when there is none. The files in /clara are the system's own Lisp: the language's part that is written in Lisp, the console, the drivers and the file system. /EFI holds the kernels.

Reading and loading

> (with-open-file (in "/clara/listener.lisp") (list (read-line in) (read-line in)))
(";;;; listener.lisp: read, evaluate, print" ";;;;")
> (load "/clara/listener.lisp")
T

with-open-file opens a file for the forms inside it and closes it afterwards. read-line gives the next line, and at the end of the file it is an error, or the value you name: (read-line in nil 'done). load evaluates the forms of a file one after the other, as if they had been typed. When a form in it fails, the error says the file and the line.

Writing

> (with-open-file (out "/notes.txt" :direction :output)
    (format out "milk~%eggs~%"))
NIL
> (with-open-file (in "/notes.txt") (list (read-line in) (read-line in) (read-line in nil 'no-more)))
("milk" "eggs" NO-MORE)
> (with-open-file (out "/notes.txt" :direction :output) (write-line "bread" out))
error: OPEN: there is a file /notes.txt already, and :IF-EXISTS does not say :SUPERSEDE or :APPEND
> (with-open-file (out "/notes.txt" :direction :output :if-exists :append) (write-line "bread" out))
"bread"
> (with-open-file (out "/hello.lisp" :direction :output)
    (format out "(defun hello () (format t ~S))~%" "hello from a file~%"))
NIL
> (load "/hello.lisp")
T
> (hello)
hello from a file
NIL
> (delete-file "/notes.txt")
T
> (probe-file "/notes.txt")
NIL

A file is opened for writing with :direction :output, and whatever prints to a stream prints to it: format, write-line, print. The file is made when with-open-file is over. If the forms inside it fail, no file is made, and one that was there stays as it was.

:if-existswhen there is a file of that name already
:erroran error, which is what happens when nothing is said
:supersedethe new file takes its place
:appendwhat is written goes after what the file holds
nilno stream: open gives NIL, and nothing is written

What to know about files as they are now:

  • A file is text, in UTF-8. It is read whole when it is opened and written whole when it is closed, so it has to fit in memory, which a text does.
  • A name can be 255 characters long and have spaces in it. It cannot have any of " * : < > ? \ | in it, or end in a dot or a space.
  • Directories cannot be made, and a file cannot be renamed or moved. A new file goes into a directory that is there.
  • There is no clock in the system, so every file it writes is dated the first of January 1980.
  • The disk is a FAT volume, which other systems read. On macOS, build/claraos.img opens with a double click, and the files that ClaraOS wrote are in it.

{{spleen:Saving the world}}

Everything that you define lives in the machine's memory, and is gone when the machine stops, unless you save it. clara:save-image writes the whole Lisp world to one file on the disk, as it is at that moment.

> (clara:save-image)
"/clara/clara.image"

The next time the machine starts, it finds that file and takes it for its world, in place of loading the Lisp files. The report says so:

lisp: the heap is an image: 1542 KiB that ClaraOS {{version}} saved, from clara.image on the boot volume

And at the prompt, what was defined is defined:

> (fact 10)
3628800
> (hello)
hello from a file
NIL
> (list (depth) (point-x (make-point :x 1)) (unless-zero 2 'two))
(0 1 TWO)
> (probe-file "/clara/clara.image")
"/clara/clara.image"

What comes back, and what does not

  • Functions, macros, structures, packages and conditions that were defined, and the values of variables, come back. So does the package that names were being read in.
  • A special variable comes back with the value it has outside every let, also when it was saved from inside one.
  • Threads do not come back. The world starts again at the prompt, and does not go on in the middle of what it was doing. A thread that was running is one that has been stopped, and a lock that was held is free.
  • The devices are found again, as at every start. A world can be saved on one machine and started on another that has other devices, or another screen, as long as it is the same kind of processor.
  • Files are on the disk either way, and have nothing to do with the image.

Saving again writes a new image in place of the old one. A world of this size takes a fraction of a second to save.

Going back to the files

> (delete-file "/clara/clara.image")
T

Without the image, the next start loads the Lisp files again, and the world is as new. A disk that nothing was saved on does the same: under QEMU, delete build/disk-aarch64.img and it is made anew; in UTM, import build/claraos.img again.

An image that is not taken

When the system cannot use an image, it says why in its report and starts from the Lisp files, as if there had been none. The image stays on the disk until it is deleted or saved over.

The report sayswhich means
it was saved on ARM64, and this machine is X86-64An image is for the kind of processor it was saved on.
it is not what was saved, by its checksumThe file was damaged, or changed, since it was written.
it is 775020 bytes long, and not as long as it says it isThe file is not whole: the machine stopped while it was being written, or it was cut short on the way.
it does not begin the way an image doesSome other file has the image's name.
ClaraOS 0.0.14 saved it, with objects that are not laid out as they are hereThe image is from a version whose memory was arranged otherwise. Images of other versions are taken as long as that has not changed.
it has the function FOO in C, and this kernel has none of that nameThe image was saved by a newer system than the one that is starting.
the machine has no memory for its heapThe world was saved on a machine with more memory.

A newer ClaraOS starts an older image, and what it has more of is there. What the older world defined in Lisp stays as it was saved, the system's own files included. To have those as the newer system has them, delete the image, start again, and save a new one.

One thing an image cannot be saved from is itself. A world in which something essential was redefined and then saved starts like that every time, and if it cannot get to its prompt it cannot delete its own image. The way out is a disk without the image: the two at the end of Going back to the files.

{{spleen:Threads}}

A thread is a function that runs beside the others. The prompt is one thread, the listener, and each keyboard and pointer has one. The names are those that Bordeaux Threads made usual, in the package CLARA.

> (clara:current-thread)
#<THREAD "listener">
> (clara:join-thread (clara:make-thread (lambda () (* 6 7)) :name "worker"))
42
> (defvar *jobs* 0)
*JOBS*
> (let ((lock (clara:make-lock)))
    (mapc #'clara:join-thread
          (mapcar (lambda (n) (clara:make-thread (lambda () (clara:with-lock-held (lock) (incf *jobs* n)))))
                  '(1 2 3)))
    *jobs*)
6
> (let ((bell (clara:make-event "bell")))
    (clara:make-thread (lambda () (sleep 1) (clara:signal-event bell)))
    (clara:wait-event bell))
T
> (clara:join-thread (clara:make-thread (lambda () (car 5)) :name "faulty"))
error in #<THREAD "faulty">: CAR wants a list, and 5 is not one
error: the thread #<THREAD "faulty"> ended with an error: CAR wants a list, and 5 is not one
> (defvar *spinner* (clara:make-thread (lambda () (do () (nil))) :name "spinner"))
*SPINNER*
> (clara:thread-alive-p *spinner*)
T
> (clara:destroy-thread *spinner*)
T
> (clara:join-thread *spinner*)
error: the thread #<THREAD "spinner"> was stopped
  • clara:make-thread starts a function of no arguments in a thread of its own, and clara:join-thread waits for it and gives what the function gave.
  • A thread that ends with an error says so on the console, and the error is what join-thread then reports. The other threads go on.
  • A lock is held by one thread at a time. clara:with-lock-held takes it for the forms inside and gives it back whichever way they end.
  • An event counts how often it was signalled. clara:wait-event waits until it has been, and takes one off the count. With a number of milliseconds as its second argument it waits no longer than that, and gives NIL when the time ran out.
  • (sleep 2) waits two seconds. The other threads run meanwhile.
  • clara:destroy-thread tells a thread to stop, which it does at its next step, cleaning up on its way out.

The threads take turns, a hundredth of a second each. One of them at a time is evaluating, on the one processor that the system uses, so threads keep the machine answering while something waits, and do not make a computation faster. Each thread has its own bindings of the special variables: one that it binds with let is bound for it alone. A thread costs about a mebibyte and a half of memory.

Files from outside, and to it

The disk is an ordinary disk image with a FAT volume on it, and the computer that the virtual machine runs on can open it, while the machine is stopped. On macOS, double-click build/disk-aarch64.img in the Finder, or build/claraos.img for the one UTM was given. Put files there or take them, eject it, and start the machine. macOS leaves a few files of its own on such a volume, whose names begin with a dot. On Linux:

sudo mount -o loop,offset=1048576 build/disk-x86_64.img /mnt

Memory and devices by hand

The package CLARA.UNSAFE is what the drivers are written with: memory by its address, the I/O ports, page frames, and interrupts. It is there at the prompt as well, and it is called what it is. There is nothing between a Lisp program and the machine here but the language, and these functions are the way round the language: a wrong address written to is a mistake in the kernel itself.

> (let ((page (clara.unsafe:allocate-memory 1)))
    (setf (clara.unsafe:memory-32 page) #xC1A4A)
    (prog1 (list (clara.unsafe:memory-8 page) (clara.unsafe:memory-16 page))
      (clara.unsafe:free-memory page 1)))
(74 6730)
> (clara.unsafe:memory-8 0)
error: nothing is mapped at #x0

{{spleen:When something goes wrong}}

What you seeWhat it is, and what to do
The prompt does not come back.A form is still being evaluated, or is waiting. Ctrl-C stops it.
The firmware's own Shell> prompt, and no ClaraOS.The firmware found no disk with the kernel on it. Under QEMU, run make and start again. In UTM, see that the imported drive is there and is the only one.
disk: no disk that has a driver here, and directory finds nothing.The machine's drive is not a virtio disk. In UTM, set the drive's interface to VirtIO. The system runs without a disk, and can neither read files nor save.
Nothing happens when you type in UTM's window.The machine has no keyboard that ClaraOS has a driver for: the report says input: no keyboard and no mouse that has a driver here. Add the two QEMU arguments of In UTM, or type in the serial terminal.
On AArch64 in UTM, a line about the exception level, and then nothing.The machine is emulated and not virtualized, which starts the kernel in a mode it does not handle yet. Use Virtualize on Apple silicon, or emulate x86_64.
error: the heap is fullA computation used the memory there is. It has been stopped, what it held is free again, and the prompt is back. A machine with more memory holds more.
error: the stack is fullForms nested too deep, or a function that calls itself without end.
Boxes on the screen where characters should be.The screen's font has the characters of ASCII. The characters themselves are right, and show on the serial port.
A file that was written is gone after make.Under QEMU the disk is made again whenever a build changed something. Keep what matters outside build/, by way of the host.
lisp: clara.image is not resumed in the report.A saved world could not be used, and the reason follows on the same line: An image that is not taken.
A report that begins with exception: or panic:, and a machine that stands still.The kernel, or a driver, has failed, and has stopped the machine where it was. The report says what happened in words, where, and what was in every register. Start the machine again. What was saved or written to a file before is there. Then please say what you did, with the report: that is a bug in ClaraOS.
